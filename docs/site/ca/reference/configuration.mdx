Comença amb valors predeterminats i una connexió funcional; després compara una càrrega reproduïble. Tots dos extrems accepten `[performance]`.

## Valors i camps

```toml
[performance]
memory_mib = 512
group_memory_mib = 256
max_window_mib = 64
quic_stream_window_mib = 6
quic_send_window_mib = 32
adaptive_mux = true
diagnostics_interval_secs = 0
quic_congestion = "bbr"
```

| Camp | Valor per defecte / requisit | Significat |
|---|---|---|
| `memory_mib` | `512` | Compromís lògic del procés, 16–16384 MiB |
| `group_memory_mib` | `256` | Límit de grup, des de 16 MiB fins al del procés |
| `max_window_mib` | `64` | Finestra agregada adaptativa màxima, 1–64 MiB |
| `quic_stream_window_mib` | `6` | Finestra de recepció de flux QUIC, 1–64 MiB |
| `quic_send_window_mib` | `32` | Emmagatzematge retingut d’enviament QUIC, 1–64 MiB |
| `adaptive_mux` | `true` | Activació client del nou mux TCP adaptatiu |
| `diagnostics_interval_secs` | `0` | Interval servidor: 0 desactivat, 1–3600 segons |
| `quic_congestion` | `"bbr"` | QUIC sortint: bbr, cubic, new-reno |

## Memòria i finestres

Els pressupostos registren recursos compromesos per a connexions. Una credencial comparteix pressupost de grup. `memory_mib` accepta 16–16384 MiB; el grup comença a 16 MiB i no supera el procés. Les finestres admeten 1–64 MiB dins del pressupost. Són compromisos lògics, no assignacions inicials ni límits RSS. Deixa memòria per al nucli, l'assignador, les negociacions i altres serveis.

## Mux i congestió

`adaptive_mux` s'aplica a sessions noves amb `mux = true`. Les finestres creixen segons consum i temps d'anada i tornada després de reservar recursos. `mux = false` manté Vision. Utilitza versions compatibles. `quic_congestion` tria `bbr`, `cubic` o `new-reno` per a l'enviament QUIC local; TCP continua sota control del sistema.

## Farciment

`default` afegeix una trama aleatòria de 100–1400 bytes abans i després de les primeres 16 escriptures de cada direcció, i després cada 32. `none` el desactiva. Personalitza amb `early=N,min=N,max=N,later=N`; `later=0` desactiva la fase posterior. Cal `min <= max`, `max <= 65535` i màxim superior a zero si hi ha farciment inicial. Consumeix amplada de banda addicional.

## Escriptura de ClientHello

`segment` utilitza un llindar de 64 bytes i un primer fragment de 32. `off` escriu normalment; `segment:threshold=N,first=M` personalitza. Geneva no s'accepta.

```toml
padding_scheme = "default"
tcp_evasion = "segment"
```

Són camps arrel: posa'ls abans de `[performance]`.

## Diagnòstics

Al servidor, `diagnostics_interval_secs` entre 1 i 3600 fixa l'interval; zero desactiva recollida i informes. Se separen bytes externs i de destinació, ometent adreces, SNI, credencials i contingut. La memòria lògica descriu compromisos; consulta el sistema per a l'ús real. Les escriptures acceptades són locals; confirma el lliurament a la destinació. El temps de poll no és ús de CPU. Canvia un grup d'ajustos cada vegada.
