Umbra combines a local proxy, authentication and remote transport in one client/server pair. Rust crates separate protocol parsing, cryptography and connection management for focused testing.

## How a request travels

1. The app sends a request to local SOCKS5.
2. The client establishes the configured TCP or QUIC connection and verifies identity.
3. The server connects to the app's destination and relays data.
4. Unauthenticated connections are forwarded to the cover website.

The `server`, `client` and `keygen` commands start the endpoints and generate identity keys.

## Components

`umbra-proto` defines wire types and addresses. `umbra-crypto` handles key exchange, signatures, derivation and encryption. `umbra-fingerprint` holds browser profiles and JA3/JA4 helpers; `umbra-tls` handles TLS 1.3 messages and records.

`umbra-reality` manages authentication, replay checks and destination preparation. `umbra-inner` provides multiplexing, padding and Vision. `umbra-transport` supplies TCP and QUIC. `umbra-core` coordinates configuration, SOCKS5, dispatch and resources; `umbra` is the CLI.

## Main dependency layers

```text
umbra CLI
    ↓
umbra-core
    ↓
umbra-reality · umbra-inner · umbra-transport
    ↓
umbra-tls
    ↓
umbra-crypto · umbra-fingerprint
    ↓
umbra-proto
```

`umbra-testkit` provides loopback test tools; `xtask` runs engineering checks and release builds. Consult current guides and source for implemented features.

## The website and your connection

The website provides downloads, documentation and release notes. Your endpoints run from local configuration; the website does not manage connections or store that configuration.
