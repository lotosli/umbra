Umbra verifies identity, protects transport data and forwards unauthenticated connections to a real website. You manage keys, devices and the server environment.

## Authentication and website cover

The server checks authentication before its first response. Verified clients enter the proxy path; other connections go to the cover website. The client verifies the temporary certificate's binding to the expected server identity. A bounded, expiring replay cache checks repeated authentication material. Cryptographic checks use constant-time comparisons, with dedicated secret storage and cleanup.

## Protect keys and local access

Keep `private_key` and `mldsa_seed` on the server. Share client configuration through a trusted channel, restrict file permissions and remove credentials from public logs. The local SOCKS5 proxy has no password authentication: bind it to `127.0.0.1:1080`. Set network access controls before making it available to other devices.

## Keep application encryption

Continue using HTTPS. Vision forwards already-protected application data when eligible. Device security, browser accounts and the destination service still need their own protection.

## What website cover does

Ordinary visits and unauthenticated probes receive website responses. Addresses, timing and traffic sizes can still be observed and analyzed, and the server IP can be blocked. Umbra provides a self-hosted proxy rather than the identity separation of a multi-hop anonymity network.

## Browser profiles

`chrome-latest` currently uses Chrome 150. The repository also contains Chrome 153 TCP/QUIC captures. Profiles, captures and JA3/JA4 checks cover specific features; complete equivalence with current Chrome network behavior has not been verified.

## Post-quantum algorithms

ML-DSA-65 binds the temporary certificate's public key. The X25519 + ML-KEM-768 exchange path is used only when negotiated. The standard CLI destination probe currently uses ring, which does not support ML-KEM, and the server follows the probed group. Assess the negotiated deployment rather than assuming full post-quantum protection from the presence of ML-KEM code.

## Release status and reporting

The current release is **1.0.0-alpha**, with no published evidence of a completed independent security audit. For sensitive uses, review implementation, release records and deployment conditions. Consult [GitHub Security](https://github.com/lotosli/umbra/security) for available reporting channels. Keep exploitable details, credentials and sensitive infrastructure information out of public issues.
