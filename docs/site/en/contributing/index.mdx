## Agree on the change

Feature work uses OpenSpec: propose the change, define requirements and verification scenarios, obtain human approval, then implement the task list. Documentation should match current source and retain stable IDs across all seven languages.

## Verify your work

Run formatting, lint, tests, dependency and coverage checks appropriate to the change. Rust line coverage must remain at least 90%. Parsers need boundary and error cases; cryptographic and fingerprint changes need matching vectors or capture evidence.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo deny check
cargo xtask coverage
npx --yes @fission-ai/openspec@latest validate --all --strict
```

The website has separate build, check, tests and coverage requirements in `docs/website-development.md`. Declare dependencies centrally and check license compatibility.

## Submit a reviewable change

Use Conventional Commits and explain the problem, scope and validation in the PR. Contributors must understand, review and test AI-assisted work; disclose substantial generated content and its tool in the PR or commit. Remove real credentials, private infrastructure and unpublished vulnerability details. Umbra is released under MIT.
