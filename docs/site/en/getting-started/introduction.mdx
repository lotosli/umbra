Umbra is an open-source proxy you host yourself. Run the server on your own infrastructure and the client on your device, then point your apps at its local SOCKS5 proxy. You choose the server, the transport and the apps that use it.

## Why use Umbra?

### A real website at the same entrance

Your client authenticates to establish a proxy connection. Other connections are forwarded to the real website you configure, where visitors receive the site's normal response.

### One local proxy for TCP and UDP

Send TCP requests over TCP and UDP requests over QUIC with one client and one server process. Your apps still use a single SOCKS5 address.

### Less repeated work

Connection pooling lets requests share an existing connection. Dedicated Vision connections can forward eligible, already-encrypted TLS 1.3 traffic with less outer encryption and framing. Choose a mode in the [Choose TCP, Vision or QUIC](/en/docs/concepts/transports/).

### Keep the tools you know

SOCKS5-capable apps can connect directly. A Clash-compatible client can keep handling your rules and interface while Umbra handles the remote connection. You also avoid applying for and renewing a public CA certificate for the Umbra node.

## What you'll need

- A server your device can reach, with the same Umbra version at both ends.
- A real TLS 1.3 website reachable from the server, to use as the cover site.
- An app or proxy client that supports SOCKS5.

Umbra is a command-line tool under the MIT license. No Umbra account is required; you provide and maintain the server. Existing VLESS, VMess and Trojan nodes continue to use their own clients. Both ends of an Umbra connection run Umbra.

## Start with one app

Follow the quick start, verify one request, then add your rules client or QUIC. You decide which apps use the proxy. The current release is **1.0.0-alpha**; keep a working configuration and binary available. Bind the unauthenticated local proxy to `127.0.0.1:1080`. See the security model for more detail.
