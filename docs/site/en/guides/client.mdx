Umbra provides a SOCKS5 proxy on your device. Connect an app directly, or let your existing proxy client manage rules and pass selected requests to Umbra.


## How to check the result

Run this guide’s curl command on the client computer, then configure SOCKS5 in one app. Add a rules client only after both work. Loading a page over TCP does not verify UDP; test an app that actually uses UDP separately.

## 1. Start Umbra

Set up the server first. Replace the address, website name and identity placeholders in `client.toml`:

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

`server` is the Umbra server address; `server_name` is an allowed cover website domain.

```sh
umbra client -c client.toml
```

Keep the proxy on `127.0.0.1:1080`. It has no username or password authentication.

## 2. Connect an app directly

Choose SOCKS5, enter `127.0.0.1` and port `1080`, and leave credentials blank. The app must be able to reach the same local interface; check network isolation when using containers.

```sh
curl --proxy socks5h://127.0.0.1:1080 https://example.com/
```

`socks5h` asks the proxy to handle the hostname. Other apps control DNS through their own settings.

## 3. Add a node to your rules client

Add this entry to the existing `proxies` list, add it to a proxy group, and select it:

```yaml
proxies:
  - name: Umbra Local
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```

Keep your other nodes and rules. Route the Umbra server address directly to avoid a loop through `Umbra Local`. Configure system proxy or TUN in your existing client as usual. This connection uses SOCKS5; the remote endpoint must run Umbra. Other protocol subscriptions remain with their supported clients.

## 4. Use Vision for TCP and QUIC for UDP

Merge into the full client configuration:

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
```

Enable both `listen` and `udp_listen` on the server, allow both protocols through the firewall, and choose a cover site with QUIC. `udp: true` permits UDP requests; SOCKS negotiates the relay endpoint, so it need not be UDP port 1080.

Test directly through SOCKS5 before adding rules, then test UDP separately. If UDP is unavailable, change the transport configuration manually. Umbra does not automatically switch between TCP and QUIC.
