The server authenticates Umbra clients and connects to the destinations requested by their apps. Other connections are forwarded to the website configured in `dest`.

## Choose the cover website

Check that the server can reach a real TLS 1.3 website. Use the corresponding domain in `server_names` and the client's `server_name`. For QUIC, the website must also offer a reachable QUIC/HTTP/3 service.

## Create the configuration

Run `umbra keygen` and choose a `short_id` as described in the quick start. Save this as `server.toml`, replacing all placeholders and `cover.example`:

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

`listen` selects the TCP address. Restrict access to this file because it contains the private key and signing seed.

## Start and verify

```sh
umbra server -c server.toml
```

The startup probe checks the cover website. If it fails, check the destination, website name and network connection. `prebuild = false` disables periodic refreshes only; the startup probe still runs.

Check the listening port and firewall, then try a request through a matching Umbra client. An ordinary browser or unauthenticated TLS probe receiving the cover site's certificate is expected.

## Enable QUIC if needed

Add `udp_listen = "0.0.0.0:443"` to the full configuration. TCP and UDP may share a port number. Allow the UDP port through the firewall and verify the cover website's QUIC service. Once foreground operation works, set up a background service.
