Start with defaults and a working connection, then tune against a repeatable workload. Both endpoints accept an optional `[performance]` table.

## Defaults and fields

```toml
[performance]
memory_mib = 512
group_memory_mib = 256
max_window_mib = 64
quic_stream_window_mib = 6
quic_send_window_mib = 32
adaptive_mux = true
diagnostics_interval_secs = 0
quic_congestion = "bbr"
```

| Field | Default / requirement | Meaning |
|---|---|---|
| `memory_mib` | `512` | Process logical memory commitment, 16–16384 MiB |
| `group_memory_mib` | `256` | Credential-group ceiling, 16 MiB through process limit |
| `max_window_mib` | `64` | Adaptive aggregate window maximum, 1–64 MiB |
| `quic_stream_window_mib` | `6` | QUIC stream receive window, 1–64 MiB |
| `quic_send_window_mib` | `32` | QUIC retained send storage, 1–64 MiB |
| `adaptive_mux` | `true` | Client opt-in for new adaptive TCP mux sessions |
| `diagnostics_interval_secs` | `0` | Server diagnostic interval: 0 disabled, 1–3600 seconds |
| `quic_congestion` | `"bbr"` | Outgoing QUIC: bbr, cubic, new-reno |

## Memory and windows

Budgets track resources committed to connections. Connections with the same credential share a group budget. `memory_mib` accepts 16–16384 MiB; `group_memory_mib` starts at 16 MiB and cannot exceed it. Windows accept 1–64 MiB and are clipped by available budgets.

These are logical commitments, not startup allocations or an OS RSS limit. Leave memory for the kernel, allocator, handshakes and other services. Users sharing credentials share the same group.

## Adaptive mux and congestion control

`adaptive_mux` applies to new client TCP sessions with `mux = true`. Windows grow from observed consumption and round-trip time after resources are reserved. `mux = false` keeps dedicated Vision. Use compatible endpoint versions.

`quic_congestion` selects `bbr`, `cubic` or `new-reno` for this endpoint's outgoing QUIC traffic. TCP congestion control remains an OS setting.

## Padding

`default` adds a random 100–1400-byte frame before and after each of the first 16 business writes per direction, then once per 32 writes. `none` disables padding. Customize with `early=N,min=N,max=N,later=N`; `later=0` disables later padding. Require `min <= max`, `max <= 65535`, and a nonzero maximum when early padding is enabled. Padding consumes extra bandwidth.

## Handshake writes

`segment` writes ClientHello in order, with a default 64-byte threshold and 32-byte first chunk. Use `off` for ordinary writes or `segment:threshold=N,first=M` to customize. Geneva is not accepted.

```toml
padding_scheme = "default"
tcp_evasion = "segment"
```

These are top-level fields: place them before `[performance]` or with the other top-level settings.

## Diagnostics

On the server, set `diagnostics_interval_secs` to 1–3600 seconds to collect and report numeric observations. Zero disables collection and reporting. Output separates outer and target bytes and omits addresses, SNI, credentials and payloads.

Logical commitments describe reserved resources; use OS metrics for actual memory. Accepted writes report local acceptance; verify delivery at the destination. Poll wall time describes task progress; use system metrics for CPU utilization. Change one related group of settings at a time and compare the same workload.
