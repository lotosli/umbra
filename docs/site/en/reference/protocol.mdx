Start with your network, how you want to maintain the server, and the apps you use. Umbra combines website cover, TCP/Vision, QUIC and SOCKS5 in one self-hosted client/server pair.

The comparison covers Umbra 1.0.0-alpha. Xray here means VLESS + REALITY + Vision over TCP.

## Deployment and transport

| Setup | Main features | Deployment | TCP and UDP |
| --- | --- | --- | --- |
| Umbra | Real website cover; one local proxy | Install the same Umbra version on both ends and start it from the command line. QUIC requires an open UDP port and a QUIC-capable cover website. | TCP mux or Vision; UDP can use QUIC separately |
| Xray + VLESS + REALITY + Vision | REALITY and Vision over TCP | Use the same user ID at both ends. Enter the server’s REALITY identity parameters in the client and set flow to xtls-rprx-vision. | TCP outer transport here; UDP depends on flow and client configuration |
| VMess AEAD | Encrypted proxy protocol with selectable transports | Match the user ID and transport at both ends. For WebSocket, match the path; when enabling TLS, configure the domain and certificate. | TCP and UDP requests; outer transport follows configuration |
| Trojan | TLS and website fallback | Configure the server domain, valid certificate and password, then enter that password in the client. Standard Trojan also carries UDP requests over a TCP connection. | TCP and UDP carried over TLS/TCP |
| Shadowsocks AEAD / 2022 | Key-based encrypted proxy | Match the encryption method and key on both ends; open the UDP port if needed. Configure any extra plugin at both ends according to its instructions. | Native TCP/UDP; check each plugin’s supported protocols |
| Hysteria 2 | QUIC; HTTP/3 website behavior before authentication | Open the server’s UDP port and configure TLS certificates and authentication. If the network blocks UDP, choose another working connection method. | TCP on reliable streams; UDP in unreliable datagrams |

## Where Umbra helps

Use `transport = "tcp"`, `udp_transport = "quic"` and `mux = false` for Vision TCP and QUIC UDP through one local endpoint. Run one process at each end. Identity keys and temporary certificate binding remove the need to apply for and renew a node's public CA certificate. Maintain keys and a reachable cover website; QUIC also requires a QUIC-capable site.

Apps connect through SOCKS5, while an existing rules client can keep its interface and routing. TCP mux reduces repeated connection setup; dedicated Vision reduces outer encryption for eligible TLS 1.3 traffic.

## Choose for your existing setup

- **Xray and REALITY:** weigh your routing, clients and configuration workflow against Umbra's single-entry dual-transport setup.
- **VMess:** check the transport combination and client support before planning migration.
- **Trojan:** consider its conventional TLS certificate and website-fallback setup.
- **Shadowsocks:** consider key-based encrypted proxying and any extra plugins you need.
- **Hysteria 2:** compare its datagram behavior with Umbra's reliable streams using your actual UDP applications.

Umbra is currently an Alpha CLI tool. Include graphical interfaces, mobile clients and subscription management in your decision if you need them.

## An important UDP difference

Hysteria 2 uses unreliable datagrams for UDP. Umbra currently carries UDP associations in reliable QUIC streams: missing data can hold up later data in that stream. Compare latency and loss on the actual path for calls, games and other real-time apps.
