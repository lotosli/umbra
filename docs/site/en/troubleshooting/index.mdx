Record endpoint versions, platform and the error. Reproduce with one simple request and change one setting at a time.


## How to check the result

Locate the failing step first: a refused connection to 127.0.0.1:1080 points to the local client; a remote timeout calls for checking the server process, address and port; a failed handshake calls for checking keys, short_id, server_name and both clocks. Rerun curl after the fix before returning to your app.

## Start with a direct test

```sh
umbra --help
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
```

If SOCKS5 works directly but a rules client fails, check node selection, rules, DNS and proxy loops.

## The server exits at startup

Check TOML syntax, required values, file permissions and port conflicts. Startup probes the cover website; check `dest`, website names and connectivity from the server.

## Authentication fails

Compare `public_key`, `mldsa_verify`, `short_id` and `server_name` through a trusted channel against the running server configuration. Correct system clocks before adjusting tolerance, then check the actual server port.

## The app still cannot connect

Confirm it uses SOCKS5 at `127.0.0.1:1080`. Check DNS and connectivity from the server to the app's destination. `socks5h` and `--socks5-hostname` pass the hostname to the proxy.

## TCP works but UDP fails

Check `udp_transport`. QUIC needs `udp_listen`, an open UDP firewall port and a reachable QUIC/HTTP/3 cover website. Enable UDP in the rules client and test a real UDP app separately.

## You see the cover website

An ordinary browser or unauthenticated probe receiving its certificate and response is expected. Test proxy operation with a configured Umbra client and local SOCKS5.

## The connection is slow

Compare the same destination, workload and path. Enable numeric diagnostics if needed and inspect windows, queues and budgets alongside system CPU and memory. See the performance reference for metric meanings.

## Reporting a problem

Provide versions, OS, failure stage, redacted commands and errors, and minimal reproduction steps. Remove keys, credentials, deployment addresses and user content. Follow the security reporting guidance for vulnerabilities.
