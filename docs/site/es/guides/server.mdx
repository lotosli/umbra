El servidor autentica a los clientes Umbra y conecta con los destinos que solicitan sus aplicaciones. El resto de las conexiones se reenvía al sitio de `dest`.

## Elegir el sitio

Comprueba que el servidor accede a un sitio TLS 1.3 real. Usa su dominio en `server_names` y en `server_name` del cliente. Para QUIC, el sitio también debe ofrecer QUIC/HTTP/3 accesible.

## Crear la configuración

Ejecuta `umbra keygen` y elige un `short_id` según el inicio rápido. Guarda este modelo en `server.toml`, sustituyendo los marcadores y `cover.example`:

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

`listen` define la escucha TCP. Protege este archivo: contiene la clave privada y la semilla de firma.

## Iniciar y comprobar

```sh
umbra server -c server.toml
```

Si falla la comprobación inicial del sitio, revisa destino, dominio y conectividad. `prebuild = false` desactiva solo las actualizaciones periódicas; la comprobación al arrancar sigue activa. Revisa puerto y cortafuegos y prueba un cliente configurado. Es normal que un navegador o una sonda TLS sin autenticar reciban el certificado del sitio de cobertura.

## Activar QUIC si lo necesitas

Añade `udp_listen = "0.0.0.0:443"` a la configuración completa. TCP y UDP pueden compartir número de puerto. Permite UDP y comprueba el servicio QUIC del sitio. Configura el servicio en segundo plano después de validar el funcionamiento en primer plano.
