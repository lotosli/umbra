Empieza con valores predeterminados y una conexión funcional; después compara una carga reproducible. Ambos extremos aceptan `[performance]`.

## Valores y campos

```toml
[performance]
memory_mib = 512
group_memory_mib = 256
max_window_mib = 64
quic_stream_window_mib = 6
quic_send_window_mib = 32
adaptive_mux = true
diagnostics_interval_secs = 0
quic_congestion = "bbr"
```

| Campo | Valor predeterminado / requisito | Significado |
|---|---|---|
| `memory_mib` | `512` | Compromiso lógico del proceso, 16–16384 MiB |
| `group_memory_mib` | `256` | Límite de grupo, desde 16 MiB hasta el del proceso |
| `max_window_mib` | `64` | Ventana agregada adaptativa máxima, 1–64 MiB |
| `quic_stream_window_mib` | `6` | Ventana de recepción de flujo QUIC, 1–64 MiB |
| `quic_send_window_mib` | `32` | Almacenamiento retenido de envío QUIC, 1–64 MiB |
| `adaptive_mux` | `true` | Activación cliente del nuevo mux TCP adaptativo |
| `diagnostics_interval_secs` | `0` | Intervalo servidor: 0 desactivado, 1–3600 segundos |
| `quic_congestion` | `"bbr"` | QUIC saliente: bbr, cubic, new-reno |

## Memoria y ventanas

Los presupuestos registran recursos comprometidos para conexiones. Una credencial comparte presupuesto de grupo. `memory_mib` acepta 16–16384 MiB; el grupo empieza en 16 MiB y no supera el proceso. Las ventanas admiten 1–64 MiB y se ajustan al presupuesto. Son compromisos lógicos, no reservas iniciales ni límites RSS. Deja memoria para núcleo, asignador, negociaciones y otros servicios.

## Mux y congestión

`adaptive_mux` se aplica a sesiones nuevas con `mux = true`. Las ventanas crecen según consumo y tiempo de ida y vuelta tras reservar recursos. `mux = false` mantiene Vision. Usa versiones compatibles. `quic_congestion` elige `bbr`, `cubic` o `new-reno` para el envío QUIC local; TCP sigue bajo control del sistema.

## Relleno

`default` añade una trama aleatoria de 100–1400 bytes antes y después de las primeras 16 escrituras de cada dirección, y luego cada 32. `none` lo desactiva. Personaliza con `early=N,min=N,max=N,later=N`; `later=0` desactiva la fase posterior. Se exige `min <= max`, `max <= 65535` y máximo mayor que cero si hay relleno inicial. Consume ancho de banda adicional.

## Escritura de ClientHello

`segment` usa un umbral de 64 bytes y un primer fragmento de 32. `off` escribe normalmente; `segment:threshold=N,first=M` personaliza. Geneva no se acepta.

```toml
padding_scheme = "default"
tcp_evasion = "segment"
```

Son campos raíz: colócalos antes de `[performance]`.

## Diagnósticos

En el servidor, `diagnostics_interval_secs` entre 1 y 3600 establece el intervalo; cero desactiva recogida e informes. Se separan bytes externos y del destino, omitiendo direcciones, SNI, credenciales y contenido. La memoria lógica describe compromisos; consulta el sistema para el uso real. Las escrituras aceptadas son locales; confirma entrega en destino. El tiempo de poll no es utilización de CPU. Cambia un grupo de ajustes cada vez.
