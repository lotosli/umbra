Anota versiones, plataforma y error. Reproduce una sola solicitud y cambia un ajuste cada vez.

## Prueba directa

```sh
umbra --help
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
```

Si SOCKS5 funciona y el cliente de reglas no, revisa nodo, reglas, DNS y bucles.

## El servidor se cierra al arrancar

Comprueba TOML, campos obligatorios, permisos y puertos ocupados. La comprobación inicial necesita `dest`, dominio y conectividad válidos.

## Falla la autenticación

Contrasta `public_key`, `mldsa_verify`, `short_id` y `server_name` por un canal de confianza con la configuración activa. Corrige relojes antes de tolerancias y comprueba el puerto real.

## La aplicación no conecta

Confirma SOCKS5 en `127.0.0.1:1080`, luego DNS y acceso desde el servidor al destino. `socks5h` pasa el dominio al proxy.

## TCP funciona, UDP no

Revisa `udp_transport`. QUIC necesita `udp_listen`, puerto UDP abierto y sitio QUIC/HTTP/3 accesible. Activa UDP en el cliente y prueba una aplicación UDP aparte.

## Aparece el sitio de cobertura

Es normal en un navegador o una sonda sin autenticar. Prueba el proxy con el cliente Umbra configurado y SOCKS5 local.

## La conexión es lenta

Compara el mismo destino, carga y ruta. Consulta diagnósticos, ventanas, colas y presupuestos junto a CPU y memoria del sistema. La referencia de rendimiento explica las métricas.

## Informar del problema

Incluye versiones, sistema, fase, comandos y errores sin secretos y pasos mínimos. Retira claves, credenciales, direcciones y contenido de usuarios. Para vulnerabilidades, sigue el canal de seguridad.
