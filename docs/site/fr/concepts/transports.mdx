`transport` choisit le transport des requêtes TCP. `udp_transport` peut définir un trajet distinct pour UDP ; sinon UDP reprend `transport`.


## Comment vérifier le résultat

Choisissez TCP pour la première connexion. Une fois les deux extrémités opérationnelles, essayez QUIC ou des chemins TCP/UDP distincts. Modifiez un seul paramètre à la fois et retestez avec la même application ; Umbra ne change pas automatiquement de transport.

## Par où commencer ?

Choisissez TCP pour la première connexion ou si UDP est indisponible. Activez mux pour réutiliser les connexions, ou désactivez-le pour Vision dédié. Essayez QUIC si UDP fonctionne, notamment lorsque TCP subit des réinitialisations injectées. Pour combiner les chemins, utilisez TCP et `udp_transport = "quic"`. Testez d'abord l'accès, puis la latence, la stabilité et le débit avec la même application.

## Multiplexage TCP

```toml
transport = "tcp"
mux = true
```

Les requêtes partagent des connexions chiffrées. Les fenêtres adaptatives suivent consommation et temps aller-retour dans les budgets mémoire. Une perte TCP peut faire attendre les requêtes partageant la connexion. Les deux extrémités doivent être compatibles.

## TCP / Vision dédié

```toml
transport = "tcp"
mux = false
```

Chaque requête a sa connexion. Après négociation authentifiée, les enregistrements TLS 1.3 admissibles sont transmis sans chiffrement externe ni encapsulation supplémentaire. Les autres données restent chiffrées. Conservez HTTPS dans les applications. Le relais s'effectue en espace utilisateur ; le débit dépend de l'appareil et du réseau.

## QUIC

```toml
transport = "quic"
```

QUIC utilise UDP. Activez `udp_listen`, ouvrez le port et choisissez un site de couverture QUIC accessible. Les flux distincts récupèrent leurs pertes séparément ; chaque flux fiable conserve l'ordre des données. Umbra transporte aussi les associations UDP dans des flux QUIC fiables : une perte peut y retarder les données suivantes.

Quinn BBR est utilisé par défaut ; `cubic` et `new-reno` sont disponibles. Ce choix concerne l'envoi QUIC local, séparément des paramètres TCP du système.

## Deux chemins, un proxy local

Client :

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
socks_listen = "127.0.0.1:1080"
```

Serveur :

```toml
listen = "0.0.0.0:443"
udp_listen = "0.0.0.0:443"
```

Conservez les autres champs de la configuration complète. Les applications gardent une seule entrée SOCKS5. `udp: true` autorise UDP dans Clash ; TCP suit `transport`. Modifiez les réglages lorsque le réseau change : le basculement TCP/QUIC reste manuel.

## Remplissage et écriture de la négociation

Le remplissage ajoute des données de taille aléatoire au début, puis moins souvent, pour atténuer les motifs de longueur fixes, au prix de bande passante supplémentaire. `tcp_evasion = "segment"` divise ClientHello en écritures ordonnées ; le système décide des limites des paquets. Testez `off` en cas d'incompatibilité. Geneva DSL n'est pas pris en charge.
