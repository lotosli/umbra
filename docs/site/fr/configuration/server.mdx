Le serveur utilise un fichier TOML. Pour une première installation, suivez le guide de configuration du serveur.

## Configuration minimale

Remplacez les valeurs d'identité et `cover.example` :

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

## Champs

| Champ | Valeur par défaut / exigence | Signification |
|---|---|---|
| `listen` | Obligatoire | Adresse numérique d’écoute TCP |
| `udp_listen` | `—` | Écoute QUIC UDP facultative ; omettre pour désactiver |
| `private_key` | Obligatoire | Clé privée X25519, base64, exactement 32 octets |
| `short_ids` | Obligatoire | Liste non vide d’ID hexadécimaux de 0–8 octets |
| `dest` | Obligatoire | Destination réelle de repli, hôte:port |
| `server_names` | Obligatoire | Liste non vide de SNI acceptés |
| `max_time_diff` | Obligatoire | Écart d’horloge autorisé, au moins une seconde |
| `mldsa_seed` | Obligatoire | Graine ML-DSA, base64, exactement 32 octets |
| `prebuild` | `true` | Rafraîchissement périodique ; sonde initiale obligatoire |
| `padding_scheme` | `"default"` | Politique de remplissage interne |
| `tcp_evasion` | `"segment"` | Écritures ordonnées du ClientHello |

Les paramètres de performance se placent dans `[performance]`.

## Adresses et domaines

`listen` et `udp_listen` exigent une IP numérique et un port, comme `0.0.0.0:443` ou `[::]:443`. `dest` accepte un nom d'hôte. `server_names` contient au moins un nom conforme aux limites de longueur et à la syntaxe ASCII, sans espaces. Utilisez les domaines du site réel ; le client en choisit un.

## Clés et identifiants courts

`private_key` et `mldsa_seed` sont encodés en Base64 et donnent chacun 32 octets. Utilisez les sorties correspondantes de `keygen`. `short_ids` contient au moins une chaîne hexadécimale de longueur paire, de 16 caractères maximum ; la chaîne vide est aussi acceptée. Le client doit reprendre l'une des valeurs.

## Horloge et rafraîchissement

`max_time_diff` accepte `ms`, `s`, `m`, `h`, ou des secondes sans suffixe ; la durée finale est d'au moins une seconde. Vérifiez les horloges avant d'élargir la tolérance. Le site est vérifié à chaque démarrage ; `prebuild`, activé par défaut, contrôle les rafraîchissements suivants.

## Priorité des options

Une option CLI fournie remplace le champ TOML correspondant. La validation intervient après fusion. Les options CLI utilisent des tirets, comme `--udp-listen`, et TOML des traits de soulignement. Gardez les secrets dans un fichier protégé pour éviter l'historique du shell et la liste des arguments.
