## Vue d’ensemble

Umbra pratique le développement guidé par les spécifications. Proposez un changement OpenSpec et faites approuver les exigences avant l’implémentation. Réalisez les tâches avec des tests correspondant aux scénarios. Le code Rust, les API publiques et le protocole restent soumis à AGENTS.md et aux règles de contribution du dépôt.

## Détails

Exécutez formatage, lint strict, tests, vérification des dépendances et couverture selon le changement. La couverture de lignes doit rester au moins à 90 %, sans abaisser le seuil ni inventer des tests dépourvus d’assertions utiles. Les parseurs réseau demandent des tests de limites et d’erreurs ; cryptographie et empreintes nécessitent leurs vecteurs ou preuves de capture. Centralisez les dépendances et préservez leur graphe sans cycle.
```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo deny check
cargo xtask coverage
npx --yes @fission-ai/openspec@latest validate --all --strict
```

## Vérification et limites

La documentation conserve des identifiants stables, des sources publiques actuelles et sept traductions complètes. Séparez objectifs et implémentation ; excluez secrets, infrastructure privée et vulnérabilités inédites. Une contribution assistée par IA doit être comprise, revue et testée par un humain responsable, avec divulgation des générations importantes dans la PR ou le commit. Respectez Conventional Commits et la licence MIT, tout en vérifiant la compatibilité des dépendances.
