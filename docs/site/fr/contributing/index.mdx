## Définir le changement

Les fonctionnalités suivent OpenSpec : proposition, exigences et scénarios, approbation humaine, puis implémentation. La documentation doit correspondre aux sources actuelles et conserver les mêmes identifiants dans les sept langues.

## Vérifier le travail

Exécutez formatage, lint, tests, dépendances et couverture selon le périmètre. La couverture des lignes Rust reste au moins à 90 %. Les parseurs nécessitent des cas limites et d'erreur ; cryptographie et empreintes demandent vecteurs ou captures adaptés.

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo deny check
cargo xtask coverage
npx --yes @fission-ai/openspec@latest validate --all --strict
```

Le site a ses propres contrôles dans `docs/website-development.md`. Centralisez les dépendances et vérifiez leurs licences.

## Soumettre pour revue

Utilisez Conventional Commits ; décrivez problème, périmètre et validation dans la PR. Le contributeur comprend, relit et teste le travail assisté par IA et déclare les contenus générés importants. Retirez identifiants réels, infrastructures privées et failles non publiées. Umbra est sous licence MIT.
