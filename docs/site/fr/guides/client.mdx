Umbra fournit un proxy SOCKS5 local. Une application peut s'y connecter directement ; votre client habituel peut aussi gérer les règles et lui transmettre les requêtes sélectionnées.

## 1. Lancer Umbra

Préparez le serveur, puis remplacez les valeurs dans `client.toml` :

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

`server` désigne le serveur Umbra ; `server_name`, un domaine de couverture autorisé.

```sh
umbra client -c client.toml
```

Conservez l'écoute sur `127.0.0.1:1080` : le proxy ne demande ni identifiant ni mot de passe.

## 2. Connecter une application

Sélectionnez SOCKS5, adresse `127.0.0.1`, port `1080`, sans identifiants. L'application doit accéder à cette interface locale ; vérifiez l'isolation réseau des conteneurs.

```sh
curl --proxy socks5h://127.0.0.1:1080 https://example.com/
```

`socks5h` confie le nom de domaine au proxy. Les autres applications disposent de leurs propres réglages DNS.

## 3. Ajouter un nœud au client de règles

Ajoutez cette entrée à la liste `proxies`, puis à un groupe, et sélectionnez-la :

```yaml
proxies:
  - name: Umbra Local
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```

Conservez les règles et les autres nœuds. Faites sortir directement l'adresse du serveur Umbra pour éviter une boucle via `Umbra Local`. Réglez le proxy système ou TUN dans votre client habituel. Cette liaison utilise SOCKS5 ; le serveur distant doit exécuter Umbra. Les abonnements à d'autres protocoles restent gérés par leurs clients compatibles.

## 4. Séparer les transports TCP et UDP

Ajoutez à la configuration complète du client :

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
```

Activez `listen` et `udp_listen` côté serveur, ouvrez les deux protocoles et choisissez un site compatible QUIC. `udp: true` autorise les requêtes UDP ; SOCKS négocie l'adresse du relais, sans imposer UDP 1080.

Testez d'abord SOCKS5 directement, puis les règles et enfin UDP. Si UDP est indisponible, modifiez le transport manuellement : il n'y a pas de basculement automatique TCP/QUIC.
