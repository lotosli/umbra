Validez une connexion au premier plan avant de créer le service. Sous Linux, systemd gère le processus et journald collecte les journaux.


## Comment vérifier le résultat

Après le déploiement, exécutez la commande curl du guide de démarrage depuis un autre client et vérifiez qu’une page s’affiche. Redémarrez le service, puis recommencez. Vous vérifiez ainsi l’accès distant, la lecture de la configuration et la reprise après redémarrage.

## Préparer les fichiers

Créez un utilisateur `umbra`, installez le programme dans `/usr/local/bin/umbra` et la configuration dans `/etc/umbra/server.toml`. Réservez sa lecture au compte de service et aux administrateurs. Adaptez les chemins absolus et l'utilisateur à votre installation.

## Configurer le réseau

Ouvrez le port TCP de `listen` ; pour QUIC, ajoutez `udp_listen` et le port UDP correspondant. Si une entrée de niveau 4 occupe le port public, liez Umbra à l'interface de boucle locale et transférez TCP/QUIC de façon transparente. Gardez les ports internes privés. Ce transfert nécessite une prise en charge des transports, au-delà d'un reverse proxy HTTP classique.

## Créer le service

Enregistrez dans `/etc/systemd/system/umbra-server.service` :

```ini
[Unit]
Description=Umbra Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=umbra
ExecStart=/usr/local/bin/umbra server -c /etc/umbra/server.toml
AmbientCapabilities=CAP_NET_BIND_SERVICE
NoNewPrivileges=true
Restart=on-failure
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

`CAP_NET_BIND_SERVICE` permet d'écouter sur les ports bas, dont 443. Vérifiez le compte, les chemins et les droits avant l'activation.

## Démarrer et consulter les journaux

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now umbra-server
sudo journalctl -u umbra-server -f
```

Testez ensuite une requête depuis le client.

## Ressources et entretien

L'optimisation actuelle du débit suppose au moins 1 GiB de RAM sur le serveur. Gardez de la mémoire pour le système, les tampons réseau et les autres services. Activez les diagnostics, désactivés par défaut, lorsque vous recherchez un problème. Redémarrez après un changement de configuration et conservez l'ancienne version pour pouvoir revenir en arrière.
