Le serveur authentifie les clients Umbra et joint les destinations demandées par leurs applications. Les autres connexions sont transmises au site indiqué par `dest`.

## Choisir le site

Le serveur doit pouvoir accéder à un véritable site TLS 1.3. Utilisez son domaine dans `server_names` et dans `server_name` côté client. Pour QUIC, ce site doit également proposer un service QUIC/HTTP/3 accessible.

## Créer la configuration

Exécutez `umbra keygen` et choisissez un `short_id` selon le démarrage rapide. Enregistrez ce modèle dans `server.toml` après avoir remplacé les valeurs et `cover.example` :

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

`listen` définit l'écoute TCP. Protégez ce fichier qui contient la clé privée et la graine de signature.

## Démarrer et vérifier

```sh
umbra server -c server.toml
```

Si la vérification initiale du site échoue, contrôlez la destination, le domaine et le réseau. `prebuild = false` désactive uniquement les rafraîchissements périodiques. Vérifiez le port et le pare-feu, puis testez une requête avec un client correspondant. Un navigateur ordinaire ou une sonde TLS non authentifiée reçoit normalement le certificat du site de couverture.

## Activer QUIC si nécessaire

Ajoutez `udp_listen = "0.0.0.0:443"` à la configuration complète. TCP et UDP peuvent utiliser le même numéro de port. Autorisez UDP et vérifiez le service QUIC du site. Configurez ensuite un service en arrière-plan lorsque le fonctionnement au premier plan est validé.
