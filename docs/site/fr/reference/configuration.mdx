Commencez avec les valeurs par défaut et une connexion fonctionnelle, puis comparez une charge reproductible. Les deux extrémités acceptent `[performance]`.

## Valeurs et champs

```toml
[performance]
memory_mib = 512
group_memory_mib = 256
max_window_mib = 64
quic_stream_window_mib = 6
quic_send_window_mib = 32
adaptive_mux = true
diagnostics_interval_secs = 0
quic_congestion = "bbr"
```

| Champ | Valeur par défaut / exigence | Signification |
|---|---|---|
| `memory_mib` | `512` | Engagement logique du processus, 16–16384 Mio |
| `group_memory_mib` | `256` | Plafond du groupe, de 16 Mio au plafond du processus |
| `max_window_mib` | `64` | Fenêtre agrégée adaptative maximale, 1–64 Mio |
| `quic_stream_window_mib` | `6` | Fenêtre de réception d’un flux QUIC, 1–64 Mio |
| `quic_send_window_mib` | `32` | Stockage d’envoi QUIC retenu, 1–64 Mio |
| `adaptive_mux` | `true` | Activation client du nouveau mux TCP adaptatif |
| `diagnostics_interval_secs` | `0` | Intervalle serveur : 0 désactivé, 1–3600 secondes |
| `quic_congestion` | `"bbr"` | QUIC sortant : bbr, cubic, new-reno |

## Mémoire et fenêtres

Les budgets suivent les ressources promises aux connexions. Une même identité partage un budget de groupe. `memory_mib` accepte 16–16384 MiB ; le groupe commence à 16 MiB et ne dépasse pas le processus. Les fenêtres acceptent 1–64 MiB, dans les budgets disponibles. Ce sont des engagements logiques, pas une allocation initiale ni une limite RSS du système. Réservez de la mémoire au noyau, à l'allocateur, aux négociations et aux autres services.

## Mux et congestion

`adaptive_mux` concerne les nouvelles sessions TCP avec `mux = true`. Les fenêtres croissent après réservation des ressources, selon consommation et temps aller-retour. `mux = false` conserve Vision dédié. Utilisez des versions compatibles. `quic_congestion` choisit `bbr`, `cubic` ou `new-reno` pour l'envoi QUIC local ; TCP reste réglé par le système.

## Remplissage

`default` ajoute une trame aléatoire de 100–1400 octets avant et après les 16 premières écritures métier de chaque direction, puis toutes les 32 écritures. `none` désactive le remplissage. Personnalisez avec `early=N,min=N,max=N,later=N` ; `later=0` désactive la phase ultérieure. Il faut `min <= max`, `max <= 65535`, et un maximum non nul si la phase initiale est active. Cela consomme de la bande passante.

## Écriture de ClientHello

`segment` utilise un seuil de 64 octets et un premier fragment de 32 octets. `off` écrit normalement ; `segment:threshold=N,first=M` personnalise les valeurs. Geneva n'est pas accepté.

```toml
padding_scheme = "default"
tcp_evasion = "segment"
```

Placez ces champs au niveau racine, avant `[performance]`.

## Diagnostics

Côté serveur, `diagnostics_interval_secs` entre 1 et 3600 définit la période en secondes ; zéro désactive collecte et rapport. Les valeurs distinguent transport externe et cible, sans adresses, SNI, identifiants ni contenu. Les engagements décrivent des réservations : consultez le système pour la mémoire réelle. Les écritures acceptées mesurent l'acceptation locale : vérifiez la livraison côté cible. Le temps de poll est un temps écoulé, pas l'utilisation CPU. Changez un groupe de réglages à la fois.
