Umbra は認証と通信保護を行い、未認証の接続を実在サイトへ転送します。鍵、端末、サーバーの管理は利用者が担当します。

## 認証とサイトによるカバー

サーバーは最初の応答前に認証を確認します。クライアントは一時証明書と期待するサーバーの識別情報の結び付きを検証します。他の接続はカバーサイトへ転送されます。容量と有効期間を制限したキャッシュでリプレイを確認し、暗号学的な検証には定数時間比較と専用の秘密情報保管・消去を使います。

## 鍵とローカルアクセス

`private_key` と `mldsa_seed` はサーバーに保管します。クライアント設定は信頼できる経路で渡し、ファイル権限を制限し、公開ログから認証情報を除きます。SOCKS5 はパスワードなしのため `127.0.0.1:1080` で待ち受けます。他の端末へ公開する前にアクセス制御を設定してください。

## アプリの暗号化を維持

HTTPS を引き続き使います。Vision は適用可能な暗号化済みデータを転送します。端末、アカウント、宛先サービスの安全は個別に管理します。

## カバーの範囲

通常のアクセスと未認証プローブにはサイトが応答します。接続アドレス、時刻、通信量は観測でき、サーバー IP が遮断される可能性もあります。Umbra は自主管理のプロキシであり、多段匿名ネットワークの識別情報分離は提供しません。

## ブラウザープロファイル

`chrome-latest` は Chrome 150 です。リポジトリには Chrome 153 の TCP/QUIC キャプチャーもあります。プロファイル、キャプチャー、JA3/JA4 はそれぞれ特定項目を対象としており、現在の Chrome のネットワーク動作全体との一致は未検証です。

## 耐量子アルゴリズム

ML-DSA-65 は一時証明書の公開鍵を結び付けます。X25519 + ML-KEM-768 は実際に協議された場合のみ使われます。標準 CLI の宛先プローブは ML-KEM 非対応の ring を使い、サーバーは検出したグループに従います。実際の接続で協議される方式を確認してください。

## バージョンと報告

**1.0.0-alpha** について、独立したセキュリティ監査の完了を示す公開資料はありません。重要な用途では実装、リリース記録、運用環境を確認してください。報告方法は [GitHub Security](https://github.com/lotosli/umbra/security) を参照し、悪用可能な詳細、認証情報、機微な構成を公開しないでください。
