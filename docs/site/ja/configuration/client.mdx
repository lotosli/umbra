クライアントの TOML は、リモート接続先とローカル SOCKS5 を定義します。

## 最小構成

アドレス、ドメイン、認証用の値を置き換えます。

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

## フィールド

| 項目 | 既定値 / 要件 | 意味 |
|---|---|---|
| `server` | 必須 | Umbra サーバー host:port |
| `transport` | 必須 | 主要な外側方式。tcp または quic |
| `udp_transport` | `transport` | UDP 方式。省略時は transport を継承 |
| `public_key` | 必須 | サーバー X25519 公開鍵。復号後32バイト |
| `short_id` | 必須 | サーバーが許可する short ID 一つ |
| `server_name` | 必須 | サーバーが許可する SNI |
| `fingerprint` | 必須 | 組み込みフィンガープリントの名前 |
| `mldsa_verify` | 必須 | サーバー ML-DSA 検証鍵。空でない base64 |
| `socks_listen` | 必須 | 認証なしのローカル SOCKS5 待ち受け |
| `spider_path` | `"/"` | 実サイトのパス。先頭は /、CR/LF 不可 |
| `mux` | `true` | 暗号化 mux。false は専用 TCP/Vision |
| `padding_scheme` | `"default"` | 内部パディング方式 |
| `tcp_evasion` | `"segment"` | ClientHello の順序付き分割 write |

## サーバーの認証情報を確認

`public_key` はサーバーの X25519 公開鍵で、Base64 デコード後 32 バイトです。`mldsa_verify` は対応する空でない Base64 検証鍵です。信頼できる経路で取得してください。`short_id` と `server_name` はサーバーの許可リストと一致させます。

## 通信方式を選ぶ

`transport` は必須で `tcp` または `quic` です。UDP は最終的な値を継承しますが、`udp_transport` で UDP だけ変更できます。TCP は既定で `mux = true`、false で独立 Vision を使用します。

## ローカルアクセスとプロファイル

パスワード認証がないため `socks_listen` は `127.0.0.1:1080` にします。`fingerprint` はハンドシェイクのプロファイルを選択します。`chrome-latest` と `chrome-150-macos` は現在どちらも Chrome 150 で、別名はソフトウェア更新に応じて変わります。

`spider_path` は既定で `/` です。Umbra の認証済みセッションが成立しない場合のサイト動作に使われ、`/` で始まり改行を含まない必要があります。CLI は検証前に対応値を上書きします。性能設定は `[performance]` に置き、まず既定値で接続を確認します。
