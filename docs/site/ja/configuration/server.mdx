サーバーは TOML を使います。初回構築はサーバー設定ガイドから始めてください。

## 最小構成

認証用の値と `cover.example` を置き換えます。

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

## フィールド

| 項目 | 既定値 / 要件 | 意味 |
|---|---|---|
| `listen` | 必須 | 数値 IP の TCP 待ち受け |
| `udp_listen` | `—` | 任意の QUIC UDP 待ち受け。省略で無効 |
| `private_key` | 必須 | X25519 秘密鍵。base64 復号後32バイト |
| `short_ids` | 必須 | 0〜8バイトの16進 ID。リストは1件以上 |
| `dest` | 必須 | 実際のフォールバック先 host:port |
| `server_names` | 必須 | 許可する SNI のリスト。空は不可 |
| `max_time_diff` | 必須 | 時刻の許容差。最低1秒 |
| `mldsa_seed` | 必須 | ML-DSA 署名シード。base64 復号後32バイト |
| `prebuild` | `true` | 接続先の定期更新。起動検査は常に実行 |
| `padding_scheme` | `"default"` | 内部パディング方式 |
| `tcp_evasion` | `"segment"` | ClientHello の順序付き分割 write |

性能設定は `[performance]` に記述します。

## アドレスとドメイン

`listen` と `udp_listen` には `0.0.0.0:443`、`[::]:443` のような数値 IP とポートを指定します。`dest` はホスト名も使えます。`server_names` は一つ以上で、長さ制限と ASCII の構文を満たし、空白を含まない名前が必要です。実在サイトのドメインを指定し、クライアントはその中から選びます。

## 鍵と短い ID

`private_key` と `mldsa_seed` はそれぞれデコード後 32 バイトとなる Base64 値です。`keygen` の対応出力を使います。`short_ids` は一つ以上の 16 進数文字列で、偶数長、最大 16 文字です。空文字列も受理されます。クライアントの値を一致させてください。

## 時刻とサイト情報の更新

`max_time_diff` は `ms`、`s`、`m`、`h`、または単位なしの秒数を受け付け、最終的な長さは 1 秒以上です。許容差を広げる前に時計を確認します。起動時は毎回サイトを検査し、既定で有効な `prebuild` がその後の定期更新を制御します。

## コマンドラインの優先順位

指定した CLI オプションが対応フィールドを上書きし、結合後に必須値、型、未知フィールドを検査します。CLI は `--udp-listen` のようなハイフン、TOML はアンダースコアを使います。秘密は履歴やプロセス引数に残さず、保護されたファイルに保存してください。
