開始前に `CONTRIBUTING.md` と `AGENTS.md` を読んでください。

## 変更内容を合意

機能開発は OpenSpec に従い、提案、要件と検証シナリオ、人による承認、実装の順で進めます。文書は現在のコードに合わせ、七言語で共通 ID を維持します。

## 変更を検証

範囲に応じて整形、lint、テスト、依存関係、カバレッジを確認します。Rust の行カバレッジは 90% 以上が必要です。解析器は境界・エラーケース、暗号や指紋は対応ベクトル・キャプチャーで検証します。

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo deny check
cargo xtask coverage
npx --yes @fission-ai/openspec@latest validate --all --strict
```

Web サイト固有の検査は `docs/website-development.md` にあります。依存関係は一元管理し、ライセンスを確認します。

## レビューに提出

Conventional Commits を使い、PR に問題、範囲、検証を記載します。AI 支援の成果も提出者が理解・確認・テストし、大きな生成部分を明示します。実際の認証情報、非公開構成、未公表の脆弱性は除いてください。Umbra は MIT ライセンスです。
