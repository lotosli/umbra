Umbra は、自分でサーバーを用意して使うオープンソースのプロキシです。サーバーと手元の端末で Umbra を起動し、アプリをローカルの SOCKS5 プロキシにつなぎます。接続先のサーバーも、通信方式も、利用するアプリも自分で選べます。


自分でサーバーを管理し、特定のアプリを接続したい場合は、最小限の TCP 設定から始めましょう。まず 1 台のクライアントで接続を確認してから、普段使っているルーティングツールを追加します。最初からすべての伝送設定を調整する必要はありません。
## Umbra を使うメリット

### 通常のアクセスには実在するサイトを表示

認証されたクライアントはプロキシに接続します。それ以外の接続は設定した実在のサイトに転送され、サイトの通常の応答を受け取ります。

### TCP と UDP を一つの入口に

TCP の要求は TCP、UDP の要求は QUIC で送る構成を、クライアントとサーバー各一つのプロセスで運用できます。アプリに設定する SOCKS5 のアドレスは一つのままです。

### 接続と暗号化の重複を削減

多重化では既存の接続を再利用します。独立した Vision 接続では、条件を満たす TLS 1.3 の暗号化済みデータをそのまま転送し、外側の暗号化と追加の処理を減らせます。

### 使い慣れたツールをそのまま利用

SOCKS5 対応アプリは直接接続できます。Clash 系クライアントの画面やルールを使い続け、リモート通信を Umbra に任せることもできます。Umbra ノード用に公開 CA 証明書を取得・更新する作業も不要です。

## 用意するもの

到達可能なサーバー、両端で同じバージョンの Umbra、サーバーからアクセスできる TLS 1.3 対応の実在サイト、SOCKS5 対応のアプリを用意してください。Umbra は MIT ライセンスのコマンドラインツールで、アカウント登録は不要です。サーバーの準備と管理は利用者が行います。既存の VLESS、VMess、Trojan ノードは各対応クライアントで利用し、Umbra の接続には両端で Umbra を実行します。

## まずは一つのアプリから

クイックスタートで接続を確認してから、ルールや QUIC を追加します。プロキシを使うアプリは自分で選びます。現行版は **1.0.0-alpha** です。動作する設定と実行ファイルを保管してください。ローカルプロキシにはパスワード認証がないため、`127.0.0.1:1080` で待ち受けます。詳しくはセキュリティモデルを参照してください。
