Umbra は端末上に SOCKS5 プロキシを提供します。アプリを直接接続するほか、既存クライアントのルールで選んだ通信を Umbra に渡せます。


## 結果を確認するには

まずクライアントのパソコンで本文の curl コマンドを実行し、次に 1 つのアプリで SOCKS5 を設定します。両方が動作してからルール管理用クライアントを追加してください。TCP でページを開けても UDP の確認にはならないため、UDP を使うアプリは別途確認します。

## 1. Umbra を起動

サーバーを準備し、`client.toml` の値を置き換えます。

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

`server` は Umbra サーバーのアドレス、`server_name` は許可されたカバーサイトのドメインです。

```sh
umbra client -c client.toml
```

ユーザー名・パスワード認証がないため、`127.0.0.1:1080` を維持します。

## 2. アプリを直接接続

SOCKS5、`127.0.0.1`、ポート `1080` を指定し、認証欄は空にします。アプリから同じローカルインターフェースに到達できる必要があります。コンテナーではネットワーク分離も確認してください。

```sh
curl --proxy socks5h://127.0.0.1:1080 https://example.com/
```

`socks5h` はドメイン名をプロキシに渡します。他のアプリの DNS 動作は各設定で管理します。

## 3. ルール用クライアントにノードを追加

既存の `proxies` に追加し、使用するグループに入れて選択します。

```yaml
proxies:
  - name: Umbra Local
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```

他のノードとルールは維持します。ループを防ぐため、Umbra サーバーのアドレスは `Umbra Local` を経由せず直接接続させてください。システムプロキシや TUN は既存クライアントで設定します。この接続は SOCKS5 を利用し、リモート側には Umbra が必要です。他のプロトコルのサブスクリプションは対応クライアントで扱います。

## 4. TCP は Vision、UDP は QUIC に

完全なクライアント設定に追加します。

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
```

サーバーで `listen` と `udp_listen` を有効にし、両方を許可して QUIC 対応サイトを選びます。`udp: true` は UDP 要求を許可します。中継先は SOCKS が協議するため UDP 1080 固定ではありません。

まず SOCKS5 を直接試し、次にルール、最後に UDP を個別に確認します。UDP が使えない場合は手動で設定を変更してください。TCP/QUIC の自動切り替えはありません。
