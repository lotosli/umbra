利用できるネットワーク、管理方法、既存アプリから選びます。Umbra はサイトによるカバー、TCP/Vision、QUIC、SOCKS5 を組み合わせます。対象は Umbra 1.0.0-alpha で、Xray は TCP 上の VLESS + REALITY + Vision を指します。


内容確認日：2026-09-18.

## 構築と通信方式

| 構成 | 主な特徴 | 構築 | TCP と UDP |
| --- | --- | --- | --- |
| Umbra | 実在サイトのカバーと一つのローカル入口 | 両端に同じバージョンの Umbra をインストールし、コマンドラインで起動します。QUIC を使う場合は UDP ポートを開放し、QUIC 対応のカバーサイトを選びます。 | TCP mux または Vision。UDP は別途 QUIC を選択可能 |
| Xray + VLESS + REALITY + Vision | TCP 上の REALITY と Vision | 両端に同じユーザー ID を設定します。クライアントにはサーバーに対応する REALITY の認証情報を入力し、flow を xtls-rprx-vision に設定します。 | ここでは外側 TCP。UDP は flow とクライアントに依存 |
| VMess AEAD | 通信方式を選べる暗号化プロトコル | 両端のユーザー ID と伝送方式を合わせます。WebSocket ではパスを合わせ、TLS を有効にする場合はドメインと証明書を設定します。 | TCP/UDP 要求。外側は設定に従う |
| Trojan | TLS とサイトへのフォールバック | サーバーのドメイン、有効な証明書、パスワードを設定し、クライアントにも同じパスワードを入力します。標準の Trojan は UDP 通信も TCP 接続内で転送します。 | TCP と UDP を TLS/TCP 上で伝送 |
| Shadowsocks AEAD / 2022 | 鍵による暗号化プロキシ | 両端の暗号方式と鍵を合わせます。UDP が必要なら該当ポートを開放します。追加プラグインは各プラグインの手順に従って設定します。 | 基本は TCP/UDP。プラグインの対応を個別確認 |
| Hysteria 2 | QUIC。未認証時は HTTP/3 サイトとして応答 | サーバーの UDP ポートを開放し、TLS 証明書と認証情報を設定します。ネットワークが UDP を遮断している場合は、別の接続方法を選びます。 | TCP は信頼性ストリーム、UDP は非信頼性データグラム |

## Umbra でまとめられること

`transport = "tcp"`、`udp_transport = "quic"`、`mux = false` で TCP は Vision、UDP は QUIC にし、一つのローカル入口を使えます。各端で一つのプロセスが動きます。鍵と一時証明書によりノード用の公開 CA 証明書の取得・更新を省けます。鍵と到達可能なサイトを管理し、QUIC 利用時はサイトも対応させます。

SOCKS5 で既存アプリとルールを維持できます。mux は再接続を、Vision は適用可能な TLS 1.3 の外側の暗号化を減らします。

## 既存環境から選ぶ

Xray/REALITY では現在のルーティング、クライアント、管理方法と Umbra の一入口・二経路構成を比べます。VMess は移行前に通信構成を確認します。Trojan は一般的な TLS 構築、Shadowsocks は鍵と必要なプラグインによる暗号化プロキシを検討できます。QUIC では実際の UDP アプリで Hysteria 2 と比較してください。Umbra は Alpha の CLI なので、GUI、モバイル、サブスクリプション管理の要否も考慮します。

## UDP の重要な違い

Hysteria 2 は非信頼性データグラム、Umbra は信頼性 QUIC ストリームで UDP 関連付けを運びます。後者では欠けたデータが後続を待たせることがあります。通話やゲームでは実際の経路で遅延と損失を比較してください。

## 詳細

接続の流れはアーキテクチャ、プロファイルと暗号協議はセキュリティモデルを参照してください。Geneva DSL、0-RTT、フォールバック先への事前接続は利用できません。速度と安定性は同じ負荷と経路で比較します。
