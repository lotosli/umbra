両端のバージョン、OS、エラーを記録します。一つの要求で再現し、設定は一項目ずつ変更してください。


## 結果を確認するには

まず失敗している箇所を確認します。127.0.0.1:1080 への接続拒否ならローカルクライアント、リモート接続のタイムアウトならサーバープロセス・アドレス・ポート、ハンドシェイク失敗なら鍵・short_id・server_name・両端の時計を確認します。修正後は curl を再実行してからアプリで確認してください。

## 直接接続を試す

```sh
umbra --help
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
```

SOCKS5 は動作しルールクライアントでは失敗する場合、ノード選択、ルール、DNS、ループを確認します。

## サーバーが起動直後に終了

TOML、必須項目、権限、ポート競合を確認します。起動検査には有効な `dest`、ドメイン、到達性が必要です。

## 認証に失敗

`public_key`、`mldsa_verify`、`short_id`、`server_name` を信頼できる経路で実行中の設定と照合します。許容差より先に時計を修正し、実際のポートを確認します。

## アプリから接続できない

SOCKS5 `127.0.0.1:1080` を使用しているか確認し、次にサーバーから宛先への DNS と接続を確認します。`socks5h` はドメインをプロキシへ渡します。

## TCP は動くが UDP は失敗

`udp_transport` を確認します。QUIC には `udp_listen`、開放 UDP ポート、到達可能な QUIC/HTTP/3 サイトが必要です。クライアントで UDP を有効にし、UDP アプリを個別に試します。

## カバーサイトが表示される

通常のブラウザーや未認証プローブでは正常です。設定済み Umbra クライアントと SOCKS5 で確認してください。

## 速度が出ない

同じ宛先、負荷、経路で比較します。診断、ウィンドウ、キュー、予算を OS の CPU・メモリ指標と併せて確認します。指標の意味は性能リファレンスにあります。

## 問題を報告

バージョン、OS、失敗段階、秘密を除いたコマンドとエラー、最小再現手順を添えます。鍵、認証情報、実環境のアドレス、ユーザーデータは除きます。脆弱性はセキュリティ報告手順に従ってください。
