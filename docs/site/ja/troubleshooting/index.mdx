## 概要

インストール済みバージョン、失敗段階、秘密を除いた最小設定の説明から始めます。複数の変更前に要求を一つ再現します。アプリが SOCKS を使っていない場合、両端間の障害、サーバーから実サイトまたは業務ターゲットへの障害を区別してください。それぞれ確認する箇所が異なります。

## 詳細

即座に終了する場合は TOML、必須項目、ポート競合、起動時検査を確認します。解析エラーは安全な種類と位置を示し、秘密を再表示しません。認証失敗では公開識別鍵、short ID、server_name を信頼できる経路で照合します。max_time_diff を広げる前に時計を同期します。公開 TCP ポートと、QUIC 利用時の UDP も確認します。

### 接続の確認

```sh
umbra --help
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
```


## 確認と制約

未認証検査で本物の証明書が見えるのは正常です。UDP だけ失敗するなら udp_transport、udp_listen、ファイアウォール、接続先の実 QUIC を調べます。性能問題には一定の負荷と任意診断を使い、論理メモリや受理済み write を配送指標と混同しないでください。報告には版、OS、秘密を除いたコマンド、エラー種別を含め、実設定、秘密鍵、ユーザー通信のキャプチャ、稼働中の設備情報は添付しません。
