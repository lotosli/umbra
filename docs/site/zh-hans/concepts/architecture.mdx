Umbra 将本地代理、连接认证和远端传输组合在同一套客户端与服务端中。代码按职责拆分为 Rust crate，便于分别测试协议解析、密码学运算和连接管理。

## 一次请求如何到达目标

1. 应用将请求交给本地 SOCKS5 入口。
2. 客户端按配置与 Umbra 服务端建立 TCP 或 QUIC 连接，并验证身份。
3. 服务端连接应用请求的目标，在两端之间转发数据。
4. 未通过 Umbra 身份验证的连接转发到配置的掩护网站。

`server`、`client`、`keygen` 三个 CLI 子命令分别负责启动两端和生成身份密钥。

## 组件分工

| 组件 | 职责 |
| --- | --- |
| `umbra-proto` | 协议数据格式、地址和基础类型 |
| `umbra-crypto` | 密钥交换、签名、密钥派生与加密校验 |
| `umbra-fingerprint` | 浏览器握手档案及 JA3/JA4 辅助工具 |
| `umbra-tls` | TLS 1.3 握手与记录处理 |
| `umbra-reality` | 身份认证、重放检查和目标网站信息准备 |
| `umbra-inner` | 连接复用、流量填充和 Vision |
| `umbra-transport` | TCP 与 QUIC 传输 |
| `umbra-core` | 配置、本地 SOCKS5、连接分派和资源管理 |
| `umbra` | 命令行入口 |

## 依赖方向

下图概括主要依赖层次：

```text
umbra CLI
    ↓
umbra-core
    ↓
umbra-reality · umbra-inner · umbra-transport
    ↓
umbra-tls
    ↓
umbra-crypto · umbra-fingerprint
    ↓
umbra-proto
```

`umbra-testkit` 提供本地回环测试工具，`xtask` 负责工程检查和发布构建。具体功能以当前版本的使用指南和源码为准。

## 网站与运行程序

官网提供下载、文档和版本说明。客户端与服务端通过本地配置运行，官网不参与管理你的连接或保存配置。
