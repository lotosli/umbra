客户端配置使用 TOML，包含远端服务端信息和本地 SOCKS5 入口。首次接入可先阅读[客户端指南](/zh-hans/docs/guides/client/)。

## 最小配置

替换服务器地址、网站名称和全部身份占位值：

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

## 配置字段

| 字段 | 默认值 / 要求 | 含义 |
|---|---|---|
| `server` | 必填 | Umbra 服务端地址，域名或 IP 加端口 |
| `transport` | 必填 | TCP 请求使用的传输：tcp 或 quic |
| `udp_transport` | `transport` | UDP 请求使用的传输；省略时使用 transport |
| `public_key` | 必填 | 服务端 X25519 公钥，Base64 编码，解码后为 32 字节 |
| `short_id` | 必填 | 服务端允许的一个 short ID |
| `server_name` | 必填 | 服务端允许的掩护网站域名（SNI） |
| `fingerprint` | 必填 | 浏览器握手档案名称 |
| `mldsa_verify` | 必填 | 服务端 ML-DSA 验证密钥，非空 Base64 值 |
| `socks_listen` | 必填 | 本地 SOCKS5 监听地址；无密码认证 |
| `spider_path` | `"/"` | 访问真实网站时使用的路径，以 / 开头 |
| `mux` | `true` | TCP 连接复用；false 使用独立 Vision 连接 |
| `padding_scheme` | `"default"` | 业务数据的填充策略 |
| `tcp_evasion` | `"segment"` | TLS 握手消息的分块写入策略 |

## 匹配服务端身份

`public_key` 使用服务端 `keygen` 输出的 X25519 公钥，Base64 解码后为 32 字节。`mldsa_verify` 使用同一次生成的验证密钥，字段要求为非空 Base64 值。

`short_id` 与服务端 `short_ids` 中的一项一致；`server_name` 与 `server_names` 中的一项一致。通过可信渠道取得这些配置值。

## 分别选择 TCP 与 UDP 传输

`transport` 必填，接受 `tcp` 或 `quic`。`udp_transport` 省略时使用最终生效的 `transport`；单独设置时，只改变 UDP 请求的路径。

TCP 默认启用 `mux = true`，多个请求复用连接。设为 `false` 时使用独立 Vision 连接。具体选择见[传输模式](/zh-hans/docs/concepts/transports/)。

## 本地入口与浏览器档案

`socks_listen` 按示例绑定 `127.0.0.1:1080`，让无密码认证的代理仅供本机使用。

`fingerprint` 指定构建浏览器握手消息所用的档案。当前内置 `chrome-latest` 和 `chrome-150-macos`，两者均指向 Chrome 150 档案。该别名的版本随软件发布更新，具体说明见[安全模型](/zh-hans/docs/concepts/security-model/)。

`spider_path` 默认 `/`，用于客户端未建立 Umbra 认证会话时的真实网站访问行为。路径以 `/` 开头，不包含回车或换行。

## 覆盖配置与调整性能

命令行参数覆盖对应文件字段，合并后统一校验。性能参数单独放入 `[performance]` 表；初次连接可使用默认值，连通后再按需要调整。
