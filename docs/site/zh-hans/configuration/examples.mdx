## 概览

这些模板展示完成身份和端点配置之后的模式选择。请先按快速开始替换全部占位值；模板不是完整凭据，不能把填入真实值的文件粘贴到公开问题中。客户端与服务端使用同一二进制，也不需要仅仅为了让 UDP 使用不同传输而启动两个客户端实例。

## 详细说明

加密 TCP 多路复用使用 transport=tcp、mux=true，新的 alpha 客户端默认启用自适应流控。独立 TCP/Vision 使用 transport=tcp、mux=false；适用的内层 TLS 1.3 流量在认证边界交换后可进入拼接路径，其他流量仍保持加密。不需要额外 vision 开关，也不能把用户态拼接称为内核零拷贝。

### TCP 多路复用

```toml
transport = "tcp"
mux = true
```


### 独立 TCP / Vision

```toml
transport = "tcp"
mux = false
```


### TCP / Vision + QUIC UDP

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
socks_listen = "127.0.0.1:1080"
```


### 服务端模板

```toml
listen = "0.0.0.0:443"
udp_listen = "0.0.0.0:443"
```


### 原生 QUIC

```toml
transport = "quic"
```


### Clash SOCKS5 节点

```yaml
proxies:
  - name: Umbra
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```


## 验证与边界

单实例 TCP/Vision 加 QUIC UDP 在客户端增加 udp_transport=quic，服务端同时设置 listen 和 udp_listen。若主要请求也使用原生 QUIC，则设置 transport=quic 并省略 udp_transport，使其继承 quic。dest 需要真实 QUIC/HTTP3 支持。Clash 的 udp: true 允许 UDP ASSOCIATE，TCP 仍按 transport 处理。先验证一项变化，再根据可复现问题调整默认填充或分块策略。
