服务端配置使用 TOML。首次部署可先阅读[设置服务端](/zh-hans/docs/guides/server/)，本页用于查找字段。

## 最小配置

替换所有身份占位值，并将 `cover.example` 换为所选的真实网站：

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

## 配置字段

| 字段 | 默认值 / 要求 | 含义 |
|---|---|---|
| `listen` | 必填 | TCP 监听地址，使用 IP:端口 |
| `udp_listen` | `—` | 可选 QUIC UDP 地址；省略即关闭 |
| `private_key` | 必填 | X25519 私钥，Base64 编码，解码后为 32 字节 |
| `short_ids` | 必填 | 至少一项；每项为 0–8 字节的十六进制 ID |
| `dest` | 必填 | 掩护网站地址，域名或 IP 加端口 |
| `server_names` | 必填 | 允许的掩护网站域名列表，至少一项 |
| `max_time_diff` | 必填 | 允许的时间戳偏差，至少 1 秒 |
| `mldsa_seed` | 必填 | ML-DSA 签名种子，Base64 编码，解码后为 32 字节 |
| `prebuild` | `true` | 定期刷新目标站点信息 |
| `padding_scheme` | `"default"` | 业务数据的填充策略 |
| `tcp_evasion` | `"segment"` | TLS 握手消息的分块写入策略 |

性能选项放在独立的 `[performance]` 表中，见[性能与传输参数](/zh-hans/docs/reference/configuration/)。

## 地址和网站名称

`listen`、`udp_listen` 使用数字 IP 和端口，例如 `0.0.0.0:443`；IPv6 地址使用方括号，例如 `[::]:443`。`dest` 可以使用域名加端口。

`server_names` 至少包含一个名称。名称需满足解析器的长度和 ASCII 语法要求，并且不含空白；实际使用时填写与目标网站匹配的域名。客户端的 `server_name` 从这份列表中选择。

## 密钥与 short ID

`private_key` 和 `mldsa_seed` 均使用 Base64 编码，解码后各为 32 字节。请使用 `umbra keygen` 生成的对应输出。

`short_ids` 至少包含一项；每项使用偶数长度的十六进制字符串，最多 16 个字符。解析器也接受空字符串。客户端的 `short_id` 必须与其中一项一致。

## 时间与目标刷新

`max_time_diff` 接受 `ms`、`s`、`m`、`h` 后缀；不带后缀时以秒计，最终时长至少为 1 秒。排查认证失败时，先检查两端系统时间。

服务端每次启动都会探测目标网站。`prebuild` 控制启动后的周期刷新，默认开启。

## 命令行覆盖

命令行参数覆盖配置文件中的对应值，未提供的参数保留文件值。合并后统一检查必填项、未知字段和字段类型。命令行用 `--udp-listen` 这样的连字符名称，配置文件用 `udp_listen`。

私钥和签名种子放在受保护的配置文件中，避免出现在命令历史和进程参数中。
