你可以帮助改进使用说明、报告可复现的问题，或参与功能开发。开始前阅读仓库的 `CONTRIBUTING.md` 与 `AGENTS.md`，了解当前流程。

## 先对齐改动范围

功能开发采用 OpenSpec：先提出变更、明确需求和验证场景，完成人工评审与批准，再按任务清单实现。这样可以让评审者提前理解改动目标。

文档修改需要核对当前实现和公开来源。七语文档使用相同的稳定 ID，保持内容对应。

## 验证代码

按改动范围运行格式化、lint、测试、依赖与覆盖率检查。Rust 行覆盖率要求至少 90%。解析器需要覆盖边界和错误输入，密码学和浏览器指纹改动还需要对应向量或采样依据。

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo deny check
cargo xtask coverage
npx --yes @fission-ai/openspec@latest validate --all --strict
```

网站有独立的构建、检查、测试和覆盖率要求，详见仓库的 `docs/website-development.md`。新增依赖集中声明，并检查许可证兼容性。

## 提交可审阅的变更

使用 Conventional Commits，在 PR 中说明解决的问题、修改范围和验证结果。AI 辅助内容需要由提交者理解、审查和测试；大段生成内容在 PR 或提交说明中标注工具及范围。

提交前移除真实凭证、私有基础设施信息和未公开漏洞详情。项目以 MIT 许可证发布。
