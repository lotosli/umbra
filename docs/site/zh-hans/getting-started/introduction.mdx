Umbra 是开源的自建代理工具。你在服务器上运行服务端，在自己的设备上运行客户端，再把应用接入本地 SOCKS5 代理。服务器、连接方式和接入的应用，都由你管理。

## 为什么选择 Umbra

### 用真实网站掩护代理入口

你的客户端通过身份验证后建立代理连接。其他连接则转发到你配置的真实网站，访问者看到的是网站的正常响应。这让同一个入口既能提供代理连接，也能应对普通网站访问。

### 一个入口，分别安排 TCP 和 UDP

应用只需连接一个本地代理地址。你可以让 TCP 请求走 TCP，让 UDP 请求走 QUIC；一个客户端和一个服务端就能同时处理这两类流量，省去分别运行两套程序的麻烦。

### 减少重复建连与加密

多个请求可以复用同一条连接，减少反复建立连接的开销。也可以选择独立的 Vision 连接：对于符合条件的 HTTPS 流量，直接转发已经加密的数据，减少外层重复加密。两种模式的配置方法见[传输模式](/zh-hans/docs/concepts/transports/)。

### 继续使用熟悉的工具

支持 SOCKS5 的应用可以直接接入 Umbra。使用 Clash 类客户端时，也可以保留现有界面和分流规则，把远端连接交给 Umbra。部署节点时无需申请或续期公网 CA 证书，日常维护少一项工作。

## 开始前准备什么

- 一台客户端能够访问的服务器。
- 客户端与服务端使用同一版本的 Umbra。
- 一个从服务器可访问、支持 TLS 1.3 的真实网站，用于站点掩护。
- 支持 SOCKS5 的应用，或支持 SOCKS5 节点的代理客户端。

Umbra 以命令行程序交付，源码采用 MIT 许可证，无需注册 Umbra 账户。服务器与网络由你自行准备。现有 VLESS、VMess 或 Trojan 节点仍需使用对应客户端；连接 Umbra 时，两端都运行 Umbra。

## 从一个应用开始

先完成[快速开始](/zh-hans/docs/getting-started/quick-start/)，验证一个应用的连接，再接入规则客户端或增加 QUIC。Umbra 安装后，由你选择哪些应用使用代理。

当前版本为 **1.0.0-alpha**。试用时保留可用的旧配置和程序。本地代理默认按示例绑定 `127.0.0.1:1080`，只供本机使用；更多说明见[安全模型](/zh-hans/docs/concepts/security-model/)。
