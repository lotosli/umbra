本指南先建立 TCP 连接。准备一台服务器、一台客户端设备，并在两端安装同一版本的 Umbra。客户端需要能访问服务器，服务器需要能访问用于掩护的真实网站。


## 这一步完成后，你应该看到什么

成功的标志是：两端进程保持运行，curl 通过本地 SOCKS5 返回目标网页。只看到客户端启动还不代表远端连接成功。若请求失败，先检查服务器 TCP 端口和两端身份字段，再排查应用设置。

## 1. 生成密钥

在服务端的终端中运行：

```sh
umbra keygen
```

输出包含四项。按下面的对应关系填入配置，保管好原始输出：

| 输出名称 | 配置字段 | 保存位置 |
| --- | --- | --- |
| `x25519_private` | `private_key` | 仅服务端 |
| `mldsa_seed` | `mldsa_seed` | 仅服务端 |
| `x25519_public` | `public_key` | 客户端 |
| `mldsa_verify` | `mldsa_verify` | 客户端 |

通过可信渠道传递客户端需要的值。另行选择一个 `short_id`：使用不超过 16 个字符、长度为偶数的十六进制字符串，在两端填入相同值。`keygen` 输出中不包含这一项。

## 2. 配置并启动服务端

创建 `server.toml`，填入服务端密钥。把 `cover.example` 换成从服务器可访问、支持 TLS 1.3 的真实网站，并同步修改 `dest` 和 `server_names`。

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

尖括号中的值都需要替换。配置文件只向服务运行用户和管理员开放读取权限。

```sh
umbra server -c server.toml
```

启动时 Umbra 会探测目标网站。确认服务端成功启动，并允许客户端访问配置的 TCP 端口。

## 3. 配置并启动客户端

创建 `client.toml`。把 `198.51.100.10:443` 替换为实际服务器地址；`server_name` 与服务端允许的网站名称一致。填入第一步生成的公钥、验证密钥和选定的 `short_id`。

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

保留 `socks_listen = "127.0.0.1:1080"`，让无密码认证的本地代理只供本机使用。

```sh
umbra client -c client.toml
```

## 4. 验证第一次连接

另开一个终端，通过本地代理发起 HTTPS 请求：

```sh
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
```

收到网页响应后，可以在应用中选择 SOCKS5，地址填 `127.0.0.1`，端口填 `1080`。这里的 `--socks5-hostname` 会把目标域名交给代理处理。

前台运行的客户端和服务端都可用 `Ctrl-C` 停止。连接失败时，按[故障排查](/zh-hans/docs/troubleshooting/)逐段检查；TCP 连通后，再按需增加 QUIC。
