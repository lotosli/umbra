Umbra 客户端在设备上提供一个本地 SOCKS5 代理。应用把请求交给这个入口，再由 Umbra 连接远端服务端。你可以直接设置应用，也可以通过现有代理客户端统一管理规则。

## 1. 启动 Umbra 客户端

先完成[服务端设置](/zh-hans/docs/guides/server/)。在 `client.toml` 中填写服务器地址和匹配的身份信息，替换所有占位值：

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

`server` 填 Umbra 服务器地址；`server_name` 填服务端允许的掩护网站域名。

```sh
umbra client -c client.toml
```

保持监听 `127.0.0.1:1080`。此入口不要求用户名或密码，仅供本机应用使用。

## 2. 直接接入应用

在应用代理设置中选择 **SOCKS5**，服务器填 `127.0.0.1`、端口填 `1080`，用户名和密码留空。应用与 Umbra 客户端应运行在同一设备；容器等隔离环境还需确认能够访问该入口。

用 curl 验证一次连接：

```sh
curl --proxy socks5h://127.0.0.1:1080 https://example.com/
```

`socks5h` 会把域名交给代理处理。其他应用可在各自的代理或 DNS 设置中选择相应行为。

## 3. 在 Clash 类客户端中添加节点

将下面节点加入现有 `proxies` 列表，再加入你使用的代理组并选中它：

```yaml
proxies:
  - name: Umbra Local
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```

保留已有规则和其他节点。规则客户端继续决定哪些流量走代理，Umbra 负责远端连接。将 Umbra 服务器地址设为直连，避免它再次经过 `Umbra Local` 形成循环。

这种接法使用标准 SOCKS5。远端仍需运行 Umbra；已有 VLESS、VMess 或 Trojan 订阅继续由相应客户端处理。系统代理和 TUN 按你现有客户端的方式设置。

## 4. 分别配置 TCP 与 UDP

要让 TCP 使用 Vision、UDP 使用 QUIC，在完整客户端配置中设置：

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
```

服务端同时配置 `listen` 和 `udp_listen`，开放相应 TCP、UDP 端口，并选择支持 QUIC 的掩护网站。

Clash 节点中的 `udp: true` 用于启用 UDP 请求。UDP 中继地址通过 SOCKS5 协商，无需固定配置为 UDP 1080。TCP 与 UDP 的传输方式由 Umbra 配置分别决定。

## 检查接入结果

先直接使用 SOCKS5 验证请求，再接入规则客户端，便于区分连接问题和规则问题。需要 UDP 时，单独验证实际使用的 UDP 应用。若当前网络无法使用 UDP，可手动调整传输配置；Umbra 按配置运行，不会自动切换 TCP 与 QUIC。
