先在前台完成一次客户端到服务端的连接，再设置后台运行。以下示例使用 Linux systemd 管理服务端，通过 journald 查看日志。

## 准备程序和配置

创建专用用户 `umbra`，将程序安装到 `/usr/local/bin/umbra`，配置保存到 `/etc/umbra/server.toml`。配置文件仅向服务用户和管理员开放读取权限。

如果使用其他路径或用户，请同步修改下面的服务单元。程序和配置都使用绝对路径。

## 配置监听与防火墙

开放 `listen` 对应的公网 TCP 端口。启用 QUIC 时，还需配置 `udp_listen` 并开放对应 UDP 端口。

如果前面已有四层转发服务占用公网端口，可将 Umbra 绑定到回环地址，由入口透明转发 TCP 和 QUIC。内部端口保持仅本机可访问。此类转发需要支持相应传输协议，常规 HTTP 反向代理配置不适用。

## 创建 systemd 服务

保存为 `/etc/systemd/system/umbra-server.service`：

```ini
[Unit]
Description=Umbra Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=umbra
ExecStart=/usr/local/bin/umbra server -c /etc/umbra/server.toml
AmbientCapabilities=CAP_NET_BIND_SERVICE
NoNewPrivileges=true
Restart=on-failure
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

`CAP_NET_BIND_SERVICE` 允许服务用户绑定 443 等低端口。启用前确认用户、文件路径及权限已经就绪。

## 启动并查看日志

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now umbra-server
sudo journalctl -u umbra-server -f
```

服务启动后，再从客户端发起请求，确认后台运行正常。

## 安排资源与日常维护

当前吞吐优化以至少 1 GiB 物理内存的服务端为运行前提。设置应用内存预算时，为操作系统、内核缓冲和其他服务留出空间；具体参数见[性能与传输参数](/zh-hans/docs/reference/configuration/)。

运行诊断默认关闭，需要排查时再启用。修改配置后重启服务，并验证连接。升级时保留上一版程序和配置，方便回退。
