服务端负责接收客户端连接、验证身份，并连接应用要访问的目标。普通网站访问则转发到 `dest` 指定的掩护网站。

## 选择掩护网站

从运行 Umbra 的服务器确认网站可访问，并支持 TLS 1.3。配置中的 `server_names` 和客户端的 `server_name` 使用与该网站对应的域名。

如果准备启用 QUIC，该网站还需要提供可用的 QUIC/HTTP/3 服务。仅能通过 TCP 打开 HTTPS 页面，尚不足以验证 QUIC 路径。

## 填写配置

先运行 `umbra keygen`，按[快速开始](/zh-hans/docs/getting-started/quick-start/)取得密钥并选择 `short_id`。将下面内容保存为 `server.toml`，替换所有占位值和 `cover.example`：

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

`listen` 指定 TCP 监听地址。配置包含私钥和签名种子，请限制读取权限。

## 启动并验证

```sh
umbra server -c server.toml
```

Umbra 启动时会先探测目标网站；探测失败时会停止启动。检查目标地址、域名和服务器的网络连接后再重试。`prebuild = false` 只关闭后续周期刷新，启动探测仍会执行。

确认监听端口已开放，然后用匹配的 Umbra 客户端测试一次请求。普通浏览器或 TLS 探测工具看到掩护网站的证书，是站点转发路径的正常结果。

## 按需开启 QUIC

在完整配置中增加：

```toml
udp_listen = "0.0.0.0:443"
```

TCP 和 UDP 可以使用同一端口号。为实际配置的 UDP 端口设置防火墙规则，并验证真实网站的 QUIC 可达性。

前台运行验证成功后，可继续设置[后台服务](/zh-hans/docs/guides/deployment/)。
