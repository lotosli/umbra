升级前查看目标版本的说明，记录两端当前使用的版本，备份配置，并保留已经验证可用的程序。安排两端的升级时间，避免协议变化导致连接中断。

## 升级到 1.0.0-alpha

这一版本改进了加密处理、共享连接调度与 QUIC 数据接收。TCP 多路复用默认使用自适应流控：它会根据数据消耗和往返时间调整接收窗口，同时遵守内存预算。

使用自适应 mux 时，客户端与服务端需要一起升级。

```toml
[performance]
adaptive_mux = true
quic_congestion = "bbr"
```

`adaptive_mux = false` 可显式选择旧 mux 模式。该设置适用于 TCP 多路复用；`mux = false` 仍选择独立 Vision 连接，`udp_transport` 仍单独决定 UDP 的传输方式。

## 从更早版本升级

0.0.8 调整了 X25519MLKEM768 混合密钥交换的数据顺序。涉及该变化时，旧端点与新端点需要同步更新。查阅中间版本说明，确认是否还有配置或协议变化。

没有密钥轮换要求时，可以继续使用原有身份密钥、`short_id` 和网站名称。

## 升级后验证

1. 确认两端实际运行的是刚安装的程序。
2. 通过本地 SOCKS5 完成一次 HTTPS 请求。
3. 如果配置了 UDP，测试实际使用的 UDP 应用。
4. 检查进程重启后能否恢复连接。
5. 若要比较性能，保持网络路径、应用负载和测试方法一致。

QUIC 默认使用 BBR；其设置作用于 QUIC 发送，与操作系统的 TCP 拥塞控制分别管理。出现问题时，保留错误信息并按对应版本的兼容要求回退两端。
