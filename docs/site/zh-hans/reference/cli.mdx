Umbra 使用三个子命令完成日常操作：`server` 启动服务端，`client` 启动本地 SOCKS5 代理，`keygen` 生成身份密钥。

## 查看帮助

```sh
umbra --help
umbra server --help
umbra client --help
umbra keygen
```

已安装版本的具体选项可通过对应的 `--help` 查看。

## 读取和覆盖配置

使用 `-c` 或 `--config` 指定 TOML 文件。命令行选项覆盖对应字段；未提供的选项继续使用文件值。

服务端的 `--short-ids` 和 `--server-names` 接受逗号分隔的列表。`--mux`、`--prebuild` 需要显式填写 `true` 或 `false`。性能选项通过 TOML 的 `[performance]` 表设置。

## 启动服务端

```sh
umbra server -c server.toml
```

| 命令 / 选项 | 用途 |
|---|---|
| `-c, --config` | `server.toml` |
| `--listen` | TCP 监听地址，IP:端口 |
| `--udp-listen` | 覆盖配置文件中的 QUIC UDP 监听地址 |
| `--private-key` | X25519 私钥，Base64 解码后为 32 字节 |
| `--short-ids` | 至少一个十六进制 ID；每项 0–8 字节 |
| `--dest` | 掩护网站地址，host:port |
| `--server-names` | 允许的掩护网站域名列表 |
| `--max-time-diff` | 允许的时间戳偏差，至少 1 秒 |
| `--mldsa-seed` | ML-DSA 签名种子，Base64 解码后为 32 字节 |
| `--prebuild` | 周期刷新目标；启动探测始终执行 |
| `--padding-scheme` | 业务数据填充策略 |
| `--tcp-evasion` | TLS 握手消息分块写入策略 |

## 启动客户端

```sh
umbra client -c client.toml
```

| 命令 / 选项 | 用途 |
|---|---|
| `-c, --config` | `client.toml` |
| `--server` | Umbra 服务端，host:port |
| `--transport` | TCP 请求的传输：tcp 或 quic |
| `--udp-transport` | 覆盖 UDP 传输：tcp 或 quic |
| `--public-key` | 服务端 X25519 公钥，Base64 解码后为 32 字节 |
| `--short-id` | 服务端允许的一个 short ID |
| `--server-name` | 服务端允许的掩护网站域名 |
| `--fingerprint` | 浏览器握手档案名称 |
| `--mldsa-verify` | 服务端 ML-DSA 验证密钥，非空 Base64 值 |
| `--socks-listen` | 本地 SOCKS5 地址，无密码认证 |
| `--spider-path` | 真实网站访问路径；以 / 开头，不含回车或换行 |
| `--mux` | 加密多路复用；false 选择独立 TCP/Vision |
| `--padding-scheme` | 业务数据填充策略 |
| `--tcp-evasion` | TLS 握手消息分块写入策略 |

## 生成密钥

`umbra keygen` 输出 `x25519_private`、`x25519_public`、`mldsa_seed`、`mldsa_verify` 四项 Base64 值，无需额外选项。按[快速开始](/zh-hans/docs/getting-started/quick-start/)分配到两端配置。

输出中包含私钥。请保存在受保护的文件中；日常启动也优先使用配置文件，避免秘密值出现在命令历史或进程参数中。
