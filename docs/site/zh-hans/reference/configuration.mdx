建议先使用默认值完成连接，再根据实际负载调整。客户端与服务端都接受可选的 `[performance]` 表。

## 默认性能配置

```toml
[performance]
memory_mib = 512
group_memory_mib = 256
max_window_mib = 64
quic_stream_window_mib = 6
quic_send_window_mib = 32
adaptive_mux = true
diagnostics_interval_secs = 0
quic_congestion = "bbr"
```

| 字段 | 默认值 / 要求 | 含义 |
|---|---|---|
| `memory_mib` | `512` | 进程逻辑内存预算，16–16384 MiB |
| `group_memory_mib` | `256` | 凭据组预算，至少 16 MiB，且不超过进程预算 |
| `max_window_mib` | `64` | 自适应总接收窗口上限，1–64 MiB |
| `quic_stream_window_mib` | `6` | QUIC 单流接收窗口，1–64 MiB |
| `quic_send_window_mib` | `32` | QUIC 保留发送存储，1–64 MiB |
| `adaptive_mux` | `true` | 客户端新 TCP mux 会话的自适应开关 |
| `diagnostics_interval_secs` | `0` | 服务端诊断周期：0 为关闭，范围 1–3600 秒 |
| `quic_congestion` | `"bbr"` | 本端 QUIC 发送拥塞控制算法：bbr、cubic、new-reno |

## 设置内存和窗口

内存预算约束应用承诺给连接的资源。共享同一凭据的连接共用组预算；按进程和凭据组管理资源，便于控制并发连接的占用。

`memory_mib` 接受 16–16384 MiB；`group_memory_mib` 至少为 16 MiB，并且不超过进程预算。窗口字段接受 1–64 MiB，实际窗口还会根据预算裁剪。

这些值用于逻辑资源管理，并非启动时一次性分配的内存，也不是操作系统显示的 RSS 上限。为内核缓冲、分配器、握手和其他服务留出空间。共享预算以凭据为单位，多个用户共用凭据时归入同一组。

## 使用自适应 mux

`adaptive_mux` 控制客户端新建 TCP 多路复用会话的流控方式。接收窗口根据实际数据消耗和往返时间增长，增长前先申请相应预算。

这一设置在 `mux = true` 时使用。`mux = false` 继续选择独立 Vision 连接。升级自适应 mux 时，两端使用兼容版本。

## 选择 QUIC 拥塞控制

`quic_congestion` 支持 `bbr`、`cubic` 和 `new-reno`，默认 `bbr`。配置影响本端发出的 QUIC 流量；客户端与服务端可分别设置。系统 TCP 拥塞控制仍由操作系统管理。

## 设置流量填充

默认策略在每个方向前 16 次业务写入的前后，各加入一个 100–1400 字节的随机填充帧；此后每 32 次业务写入加入一个填充帧。

- `default`：使用上述默认策略。
- `none`：关闭填充。
- `early=N,min=N,max=N,later=N`：自定义早期写入次数、填充字节范围和后续间隔。`later=0` 关闭后续填充。

`min` 不得大于 `max`，`max` 不得超过 65535。启用早期填充时，`max` 必须大于零。填充增加额外带宽消耗，调整后应验证实际连接。

## 设置 TCP 握手分块

`segment` 按顺序分块写入 ClientHello，默认阈值为 64 字节、首块为 32 字节。`off` 使用普通写入，也可用 `segment:threshold=N,first=M` 自定义。当前不接受 Geneva 策略。

```toml
padding_scheme = "default"
tcp_evasion = "segment"
```

这两个字段属于顶层配置，请放在 `[performance]` 表之前或文件中的顶层字段区域。

## 启用诊断

服务端将 `diagnostics_interval_secs` 设为 1–3600，可按指定秒数输出数值诊断；设为 `0` 时关闭收集与报告。诊断区分外层传输与目标连接的字节数，并省略地址、SNI、凭据和数据内容。

阅读指标时按下列含义判断：

| 指标 | 如何理解 |
| --- | --- |
| 逻辑内存承诺 | 应用为连接保留的资源预算；实际内存占用另看操作系统指标 |
| 写入接受计数 | 本地写入接口接受的数据量；目标应用收到多少需在目标端确认 |
| 调度 poll 时间 | 任务推进过程中的墙钟耗时；CPU 使用率另看系统指标 |

每次只改一组相关参数，在相同负载下比较，再决定是否保留。
