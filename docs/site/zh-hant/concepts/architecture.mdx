Umbra 將本機代理、連線認證和遠端傳輸組合在同一套用戶端與伺服器端中。程式碼按職責拆分為 Rust crate，便於分別測試協議解析、密碼學運算和連線管理。

## 一次請求如何到達目標

1. 應用程式將請求交給本機 SOCKS5 入口。
2. 用戶端按設定與 Umbra 伺服器端建立 TCP 或 QUIC 連線，並驗證身分。
3. 伺服器端連線應用程式請求的目標，在兩端之間轉發資料。
4. 未通過 Umbra 身分驗證的連線轉發到設定的掩護網站。

`server`、`client`、`keygen` 三個 CLI 子指令分別負責啟動兩端和產生身分金鑰。

## 組件分工

| 組件 | 職責 |
| --- | --- |
| `umbra-proto` | 協議資料格式、位址和基礎類型 |
| `umbra-crypto` | 金鑰交換、簽章、金鑰派生與加密驗證 |
| `umbra-fingerprint` | 瀏覽器握手設定檔及 JA3/JA4 輔助工具 |
| `umbra-tls` | TLS 1.3 握手與記錄處理 |
| `umbra-reality` | 身分認證、重放檢查和目標網站資訊準備 |
| `umbra-inner` | 連線重複使用、流量填充和 Vision |
| `umbra-transport` | TCP 與 QUIC 傳輸 |
| `umbra-core` | 設定、本機 SOCKS5、連線分派和資源管理 |
| `umbra` | 命令列入口 |

## 依賴方向

下圖概括主要依賴層次：

```text
umbra CLI
    ↓
umbra-core
    ↓
umbra-reality · umbra-inner · umbra-transport
    ↓
umbra-tls
    ↓
umbra-crypto · umbra-fingerprint
    ↓
umbra-proto
```

`umbra-testkit` 提供本機迴路測試工具，`xtask` 負責工程檢查和發佈建置。具體功能以目前版本的使用指南和原始碼為準。

## 網站與執行程式

官網提供下載、文件和版本說明。用戶端與伺服器端透過本機設定執行，官網不參與管理你的連線或保存設定。
