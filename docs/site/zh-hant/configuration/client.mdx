用戶端設定使用 TOML，包含遠端伺服器端資訊和本機 SOCKS5 入口。第一次連接可先閱讀[用戶端指南](/zh-hant/docs/guides/client/)。

## 最小設定

替換伺服器位址、網站名稱和全部身分預留值：

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

## 設定欄位

| 欄位 | 預設值 / 要求 | 含義 |
|---|---|---|
| `server` | 必填 | Umbra 伺服器端位址，網域名稱或 IP 加連接埠 |
| `transport` | 必填 | TCP 請求使用的傳輸：tcp 或 quic |
| `udp_transport` | `transport` | UDP 請求使用的傳輸；省略時使用 transport |
| `public_key` | 必填 | 伺服器端 X25519 公開金鑰，Base64 編碼，解碼後為 32 位元組 |
| `short_id` | 必填 | 伺服器端允許的一個 short ID |
| `server_name` | 必填 | 伺服器端允許的掩護網站網域名稱（SNI） |
| `fingerprint` | 必填 | 瀏覽器握手設定檔名稱 |
| `mldsa_verify` | 必填 | 伺服器端 ML-DSA 驗證金鑰，非空 Base64 值 |
| `socks_listen` | 必填 | 本機 SOCKS5 接聽位址；無密碼認證 |
| `spider_path` | `"/"` | 存取實際網站時使用的路徑，以 / 開頭 |
| `mux` | `true` | TCP 連線重複使用；false 使用獨立 Vision 連線 |
| `padding_scheme` | `"default"` | 業務資料的填充策略 |
| `tcp_evasion` | `"segment"` | TLS 握手訊息的分塊寫入策略 |

## 匹配伺服器端身分

`public_key` 使用伺服器端 `keygen` 輸出的 X25519 公開金鑰，Base64 解碼後為 32 位元組。`mldsa_verify` 使用同一次產生的驗證金鑰，欄位要求為非空 Base64 值。

`short_id` 與伺服器端 `short_ids` 中的一項一致；`server_name` 與 `server_names` 中的一項一致。透過可信管道取得這些設定值。

## 分別選擇 TCP 與 UDP 傳輸

`transport` 必填，接受 `tcp` 或 `quic`。`udp_transport` 省略時使用最終生效的 `transport`；單獨設定時，只改變 UDP 請求的路徑。

TCP 預設啟用 `mux = true`，多個請求重複使用連線。設為 `false` 時使用獨立 Vision 連線。具體選擇見[傳輸模式](/zh-hant/docs/concepts/transports/)。

## 本機入口與瀏覽器檔案

`socks_listen` 依照範例繫結 `127.0.0.1:1080`，讓無密碼認證的代理僅供本機使用。

`fingerprint` 指定建置瀏覽器握手訊息所用的檔案。目前內置 `chrome-latest` 和 `chrome-150-macos`，兩者均指向 Chrome 150 設定檔。該別名的版本隨軟體發佈更新，具體說明見[安全模型](/zh-hant/docs/concepts/security-model/)。

`spider_path` 預設 `/`，用於用戶端未建立 Umbra 認證會話時的實際網站存取行為。路徑以 `/` 開頭，不包含回車或換行。

## 覆寫設定與調整效能

命令列參數覆寫對應檔案欄位，合併後統一驗證。效能參數單獨放入 `[performance]` 表；初次連線可使用預設值，連通後再依需求要調整。
