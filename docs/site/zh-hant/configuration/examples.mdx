## 概覽

這些模板展示完成身份和端點設定之後的模式選擇。請先按快速開始替換全部佔位值；模板不是完整憑據，不能把填入真實值的檔案貼上到公開問題中。用戶端與伺服器端使用同一二進位制，也不需要僅僅為了讓 UDP 使用不同傳輸而啟動兩個用戶端例項。

## 詳細說明

加密 TCP 多路複用使用 transport=tcp、mux=true，新的 alpha 用戶端預設啟用自適應流控。獨立 TCP/Vision 使用 transport=tcp、mux=false；適用的內層 TLS 1.3 流量在認證邊界交換後可進入拼接路徑，其他流量仍保持加密。不需要額外 vision 開關，也不能把使用者態拼接稱為核心零複製。

### TCP 多路複用

```toml
transport = "tcp"
mux = true
```


### 獨立 TCP / Vision

```toml
transport = "tcp"
mux = false
```


### TCP / Vision + QUIC UDP

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
socks_listen = "127.0.0.1:1080"
```


### 伺服器端模板

```toml
listen = "0.0.0.0:443"
udp_listen = "0.0.0.0:443"
```


### 原生 QUIC

```toml
transport = "quic"
```


### Clash SOCKS5 節點

```yaml
proxies:
  - name: Umbra
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```


## 驗證與邊界

單例項 TCP/Vision 加 QUIC UDP 在用戶端增加 udp_transport=quic，伺服器端同時設定 listen 和 udp_listen。若主要請求也使用原生 QUIC，則設定 transport=quic 並省略 udp_transport，使其繼承 quic。dest 需要真實 QUIC/HTTP3 支援。Clash 的 udp: true 允許 UDP ASSOCIATE，TCP 仍按 transport 處理。先驗證一項變化，再根據可復現問題調整預設填充或分塊策略。
