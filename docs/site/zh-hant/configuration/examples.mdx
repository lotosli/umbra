以下片段用於合併到已有的完整設定。先按[快速開始](/zh-hant/docs/getting-started/quick-start/)填好伺服器位址、金鑰和掩護網站，再選擇需要的模式。

## 多個請求重複使用 TCP 連線

```toml
transport = "tcp"
mux = true
```

適合希望減少重複建連的場景。目前版本預設使用自適應流控，需要匹配版本的伺服器端。

## 獨立 TCP / Vision 連線

```toml
transport = "tcp"
mux = false
```

對符合條件的 TLS 1.3 流量，Vision 在認證協商完成後直接轉發已加密記錄，減少重複加密。其他流量繼續通過加密通道傳輸。設定 `mux = false` 即可選擇此模式。

## TCP 使用 Vision，UDP 使用 QUIC

用戶端：

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
socks_listen = "127.0.0.1:1080"
```

伺服器端同時啟用兩個接聽：

```toml
listen = "0.0.0.0:443"
udp_listen = "0.0.0.0:443"
```

一組用戶端與伺服器端即可處理這兩條路徑。伺服器端防火牆需要放行相應 TCP、UDP 連接埠，掩護網站需要支援可存取的 QUIC/HTTP/3 服務。

## TCP 和 UDP 都使用 QUIC

```toml
transport = "quic"
```

省略 `udp_transport`，UDP 就會繼承 `transport`。如果原設定中已有該欄位，請刪除它或顯式改為 `quic`。

## 在 Clash 類用戶端中添加本機節點

```yaml
proxies:
  - name: Umbra
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```

將節點加入現有清單和代理組。`udp: true` 允許發送 UDP 請求；TCP 請求繼續按 Umbra 的 `transport` 設定處理。將 Umbra 伺服器位址設為直連，避免代理循環。

## 驗證設定

每次只切換一種模式，用同一個應用程式驗證連線。TCP 和 UDP 分別測試；需要優化時再調整填充、分塊或效能參數。
