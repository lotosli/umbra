伺服器端設定使用 TOML。第一次部署可先閱讀[設定伺服器端](/zh-hant/docs/guides/server/)，本頁用於尋找欄位。

## 最小設定

替換所有身分預留值，並將 `cover.example` 換為所選的實際網站：

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

## 設定欄位

| 欄位 | 預設值 / 要求 | 含義 |
|---|---|---|
| `listen` | 必填 | TCP 接聽位址，使用 IP:連接埠 |
| `udp_listen` | `—` | 可選 QUIC UDP 位址；省略即關閉 |
| `private_key` | 必填 | X25519 私密金鑰，Base64 編碼，解碼後為 32 位元組 |
| `short_ids` | 必填 | 至少一項；每項為 0–8 位元組的十六進制 ID |
| `dest` | 必填 | 掩護網站位址，網域名稱或 IP 加連接埠 |
| `server_names` | 必填 | 允許的掩護網站網域名稱清單，至少一項 |
| `max_time_diff` | 必填 | 允許的時間戳偏差，至少 1 秒 |
| `mldsa_seed` | 必填 | ML-DSA 簽章種子，Base64 編碼，解碼後為 32 位元組 |
| `prebuild` | `true` | 定期更新目標網站資訊 |
| `padding_scheme` | `"default"` | 業務資料的填充策略 |
| `tcp_evasion` | `"segment"` | TLS 握手訊息的分塊寫入策略 |

效能選項放在獨立的 `[performance]` 表中，見[效能與傳輸參數](/zh-hant/docs/reference/configuration/)。

## 位址和網站名稱

`listen`、`udp_listen` 使用數值 IP 和連接埠，例如 `0.0.0.0:443`；IPv6 位址使用方括號，例如 `[::]:443`。`dest` 可以使用網域名稱加連接埠。

`server_names` 至少包含一個名稱。名稱需滿足解析器的長度和 ASCII 語法要求，並且不含空白；實際使用時填寫與目標網站匹配的網域名稱。用戶端的 `server_name` 從這份清單中選擇。

## 金鑰與 short ID

`private_key` 和 `mldsa_seed` 均使用 Base64 編碼，解碼後各為 32 位元組。請使用 `umbra keygen` 產生的對應輸出。

`short_ids` 至少包含一項；每項使用偶數長度的十六進制字串，最多 16 個字元。解析器也接受空字串。用戶端的 `short_id` 必須與其中一項一致。

## 時間與目標更新

`max_time_diff` 接受 `ms`、`s`、`m`、`h` 後綴；不帶後綴時以秒計，最終時長至少為 1 秒。排查認證失敗時，先檢查兩端系統時間。

伺服器端每次啟動都會探測目標網站。`prebuild` 控制啟動後的週期更新，預設開啟。

## 命令列覆寫

命令列參數覆寫設定檔案中的對應值，未提供的參數保留檔案值。合併後統一檢查必填項、未知欄位和欄位類型。命令列用 `--udp-listen` 這樣的連字元名稱，設定檔案用 `udp_listen`。

私密金鑰和簽章種子放在受保護的設定檔案中，避免出現在指令歷史和程序參數中。
