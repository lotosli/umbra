你可以幫助改進使用說明、報告可復現的問題，或參與功能開發。開始前閱讀儲存庫的 `CONTRIBUTING.md` 與 `AGENTS.md`，瞭解目前流程。

## 先對齊改動範圍

功能開發採用 OpenSpec：先提出變更、明確需求和驗證場景，完成人工評審與批准，再按任務清單實現。這樣可以讓評審者提前理解改動目標。

文件修改需要核對目前實作和公開來源。七語文件使用相同的穩定 ID，保持內容對應。

## 驗證程式碼

按改動範圍執行格式化、lint、測試、依賴與涵蓋率檢查。Rust 行涵蓋率要求至少 90%。解析器需要覆寫邊界和錯誤輸入，密碼學和瀏覽器指紋改動還需要對應向量或採樣依據。

```sh
cargo fmt --all --check
cargo clippy --workspace --all-targets -- -D warnings
cargo nextest run --workspace
cargo deny check
cargo xtask coverage
npx --yes @fission-ai/openspec@latest validate --all --strict
```

網站有獨立的建置、檢查、測試和涵蓋率要求，詳見儲存庫的 `docs/website-development.md`。新增依賴集中聲明，並檢查授權條款兼容性。

## 提交可審閱的變更

使用 Conventional Commits，在 PR 中說明解決的問題、修改範圍和驗證結果。AI 輔助內容需要由提交者理解、審查和測試；大段產生內容在 PR 或提交說明中標注工具及範圍。

提交前移除真實認證資訊、私有基礎設施資訊和未公開漏洞詳情。項目以 MIT 授權條款發佈。
