Umbra 是開放原始碼的自建代理工具。在伺服器與自己的裝置上分別啟動 Umbra，再將應用程式連到本機的 SOCKS5 代理。伺服器、連線方式和連接的應用程式，都由你管理。

## 為什麼選擇 Umbra

### 用實際網站掩護代理入口

你的用戶端通過身分驗證後建立代理連線。其他連線則轉發到你設定的實際網站，存取者看到的是網站的正常回應。這讓同一個入口既能提供代理連線，也能應對一般網站瀏覽。

### 一個入口，分別安排 TCP 和 UDP

應用程式只需連線一個本機代理位址。你可以讓 TCP 請求走 TCP，讓 UDP 請求走 QUIC；一個用戶端和一個伺服器端就能同時處理這兩類流量，省去分別執行兩套程式的麻煩。

### 減少重複建連與加密

多個請求可以重複使用同一條連線，減少反覆建立連線的負擔。也可以選擇獨立的 Vision 連線：對於符合條件的 HTTPS 流量，直接轉發已經加密的資料，減少外層重複加密。兩種模式的設定方法見[傳輸模式](/zh-hant/docs/concepts/transports/)。

### 繼續使用熟悉的工具

支援 SOCKS5 的應用程式可以直接連接 Umbra。使用 Clash 類用戶端時，也可以保留現有介面和分流規則，把遠端連線交給 Umbra。部署節點時不必申請或續期公開網路 CA 憑證，日常維護少一項工作。

## 開始前準備什麼

- 一部用戶端能夠存取的伺服器。
- 用戶端與伺服器端使用同一版本的 Umbra。
- 一個從伺服器可存取、支援 TLS 1.3 的實際網站，用於網站掩護。
- 支援 SOCKS5 的應用程式，或支援 SOCKS5 節點的代理用戶端。

Umbra 以命令列程式交付，原始碼採用 MIT 授權條款，不必註冊 Umbra 帳戶。伺服器與網路由你自行準備。現有 VLESS、VMess 或 Trojan 節點仍需使用對應用戶端；連線 Umbra 時，兩端都執行 Umbra。

## 從一個應用程式開始

先完成[快速開始](/zh-hant/docs/getting-started/quick-start/)，驗證一個應用程式的連線，再連接規則用戶端或增加 QUIC。Umbra 安裝後，由你選擇哪些應用程式使用代理。

目前版本為 **1.0.0-alpha**。試用時保留可用的舊設定和程式。本機代理預設依照範例繫結 `127.0.0.1:1080`，只供本機使用；更多說明見[安全模型](/zh-hant/docs/concepts/security-model/)。
