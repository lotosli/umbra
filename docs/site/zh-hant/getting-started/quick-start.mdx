本指南先建立 TCP 連線。準備一部伺服器、一部用戶端裝置，並在兩端安裝同一版本的 Umbra。用戶端需要能存取伺服器，伺服器需要能存取用於掩護的實際網站。

## 1. 產生金鑰

在伺服器端的終端機中執行：

```sh
umbra keygen
```

輸出包含四項。按下面的對應關係填入設定，保管好原始輸出：

| 輸出名稱 | 設定欄位 | 保存位置 |
| --- | --- | --- |
| `x25519_private` | `private_key` | 僅伺服器端 |
| `mldsa_seed` | `mldsa_seed` | 僅伺服器端 |
| `x25519_public` | `public_key` | 用戶端 |
| `mldsa_verify` | `mldsa_verify` | 用戶端 |

透過可信管道傳遞用戶端需要的值。另行選擇一個 `short_id`：使用不超過 16 個字元、長度為偶數的十六進制字串，在兩端填入相同值。`keygen` 輸出中不包含這一項。

## 2. 設定並啟動伺服器端

創建 `server.toml`，填入伺服器端金鑰。把 `cover.example` 換成從伺服器可存取、支援 TLS 1.3 的實際網站，並同步修改 `dest` 和 `server_names`。

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

尖括號中的值都需要替換。設定檔案只向服務執行使用者和管理員開放讀取權限。

```sh
umbra server -c server.toml
```

啟動時 Umbra 會探測目標網站。確認伺服器端成功啟動，並允許用戶端存取設定的 TCP 連接埠。

## 3. 設定並啟動用戶端

創建 `client.toml`。把 `198.51.100.10:443` 替換為實際伺服器位址；`server_name` 與伺服器端允許的網站名稱一致。填入第一步產生的公開金鑰、驗證金鑰和選定的 `short_id`。

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

保留 `socks_listen = "127.0.0.1:1080"`，讓無密碼認證的本機代理只供本機使用。

```sh
umbra client -c client.toml
```

## 4. 驗證第一次連線

另開一個終端機，透過本機代理髮起 HTTPS 請求：

```sh
curl --socks5-hostname 127.0.0.1:1080 https://example.com/
```

收到網頁回應後，可以在應用程式中選擇 SOCKS5，位址填 `127.0.0.1`，連接埠填 `1080`。這裡的 `--socks5-hostname` 會把目標網域名稱交給代理處理。

前景執行的用戶端和伺服器端都可用 `Ctrl-C` 停止。連線失敗時，按[故障排查](/zh-hant/docs/troubleshooting/)逐段檢查；TCP 連通後，再依需求增加 QUIC。
