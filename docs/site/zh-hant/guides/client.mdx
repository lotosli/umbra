Umbra 用戶端在裝置上提供一個本機 SOCKS5 代理。應用程式把請求交給這個入口，再由 Umbra 連線遠端伺服器端。你可以直接設定應用程式，也可以通過現有代理用戶端統一管理規則。

## 1. 啟動 Umbra 用戶端

先完成[伺服器端設定](/zh-hant/docs/guides/server/)。在 `client.toml` 中填寫伺服器位址和匹配的身分資訊，替換所有預留值：

```toml
server = "198.51.100.10:443"
transport = "tcp"
public_key = "<X25519_PUBLIC_BASE64>"
short_id = "<SHORT_ID_HEX>"
server_name = "cover.example"
fingerprint = "chrome-latest"
mldsa_verify = "<MLDSA_VERIFY_BASE64>"
socks_listen = "127.0.0.1:1080"
```

`server` 填 Umbra 伺服器位址；`server_name` 填伺服器端允許的掩護網站網域名稱。

```sh
umbra client -c client.toml
```

保持接聽 `127.0.0.1:1080`。此入口不要求使用者名稱或密碼，僅供本機應用程式使用。

## 2. 直接連接應用程式

在應用程式代理設定中選擇 **SOCKS5**，伺服器填 `127.0.0.1`、連接埠填 `1080`，使用者名稱和密碼留空。應用程式與 Umbra 用戶端應執行在同一裝置；容器等隔離環境還需確認能夠存取該入口。

用 curl 驗證一次連線：

```sh
curl --proxy socks5h://127.0.0.1:1080 https://example.com/
```

`socks5h` 會把網域名稱交給代理處理。其他應用程式可在各自的代理或 DNS 設定中選擇相應行為。

## 3. 在 Clash 類用戶端中添加節點

將下面節點加入現有 `proxies` 清單，再加入你使用的代理組並選中它：

```yaml
proxies:
  - name: Umbra Local
    type: socks5
    server: 127.0.0.1
    port: 1080
    udp: true
```

保留已有規則和其他節點。規則用戶端繼續決定哪些流量走代理，Umbra 負責遠端連線。將 Umbra 伺服器位址設為直連，避免它再次經過 `Umbra Local` 形成循環。

這種接法使用標準 SOCKS5。遠端仍需執行 Umbra；已有 VLESS、VMess 或 Trojan 訂閱繼續由相應用戶端處理。系統代理和 TUN 按你現有用戶端的方式設定。

## 4. 分別設定 TCP 與 UDP

要讓 TCP 使用 Vision、UDP 使用 QUIC，在完整用戶端設定中設定：

```toml
transport = "tcp"
udp_transport = "quic"
mux = false
```

伺服器端同時設定 `listen` 和 `udp_listen`，開放相應 TCP、UDP 連接埠，並選擇支援 QUIC 的掩護網站。

Clash 節點中的 `udp: true` 用於啟用 UDP 請求。UDP 中繼位址通過 SOCKS5 協商，不必固定設定為 UDP 1080。TCP 與 UDP 的傳輸方式由 Umbra 設定分別決定。

## 檢查連接結果

先直接使用 SOCKS5 驗證請求，再連接規則用戶端，便於區分連線問題和規則問題。需要 UDP 時，單獨驗證實際使用的 UDP 應用程式。若目前網路無法使用 UDP，可手動調整傳輸設定；Umbra 按設定執行，不會自動切換 TCP 與 QUIC。
