先在前景完成一次用戶端到伺服器端的連線，再設定背景執行。以下範例使用 Linux systemd 管理伺服器端，通過 journald 查看紀錄。

## 準備程式和設定

創建專用使用者 `umbra`，將程式安裝到 `/usr/local/bin/umbra`，設定保存到 `/etc/umbra/server.toml`。設定檔案僅向服務使用者和管理員開放讀取權限。

如果使用其他路徑或使用者，請同步修改下面的服務單元。程式和設定都使用絕對路徑。

## 設定接聽與防火牆

開放 `listen` 對應的公開網路 TCP 連接埠。啟用 QUIC 時，還需設定 `udp_listen` 並開放對應 UDP 連接埠。

如果前面已有四層轉發服務佔用公開網路連接埠，可將 Umbra 繫結到迴路位址，由入口透明轉發 TCP 和 QUIC。內部連接埠保持僅本機可存取。此類轉發需要支援相應傳輸協議，常規 HTTP 反向代理設定不適用。

## 創建 systemd 服務

保存為 `/etc/systemd/system/umbra-server.service`：

```ini
[Unit]
Description=Umbra Server
After=network-online.target
Wants=network-online.target

[Service]
Type=simple
User=umbra
ExecStart=/usr/local/bin/umbra server -c /etc/umbra/server.toml
AmbientCapabilities=CAP_NET_BIND_SERVICE
NoNewPrivileges=true
Restart=on-failure
RestartSec=5
LimitNOFILE=65535

[Install]
WantedBy=multi-user.target
```

`CAP_NET_BIND_SERVICE` 允許服務使用者繫結 443 等低連接埠。啟用前確認使用者、檔案路徑及權限已經就緒。

## 啟動並查看紀錄

```sh
sudo systemctl daemon-reload
sudo systemctl enable --now umbra-server
sudo journalctl -u umbra-server -f
```

服務啟動後，再從用戶端發起請求，確認背景執行正常。

## 安排資源與日常維護

目前吞吐優化以至少 1 GiB 實體記憶體的伺服器端為執行前提。設定應用程式記憶體預算時，為操作系統、核心緩衝和其他服務留出空間；具體參數見[效能與傳輸參數](/zh-hant/docs/reference/configuration/)。

執行診斷預設關閉，需要排查時再啟用。修改設定後重啟服務，並驗證連線。升級時保留上一版程式和設定，方便還原。
