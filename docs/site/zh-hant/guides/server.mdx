伺服器端負責接收用戶端連線、驗證身分，並連線應用程式要存取的目標。一般網站瀏覽則轉發到 `dest` 指定的掩護網站。

## 選擇掩護網站

從執行 Umbra 的伺服器確認網站可存取，並支援 TLS 1.3。設定中的 `server_names` 和用戶端的 `server_name` 使用與該網站對應的網域名稱。

如果準備啟用 QUIC，該網站還需要提供可用的 QUIC/HTTP/3 服務。僅能通過 TCP 打開 HTTPS 頁面，尚不足以驗證 QUIC 路徑。

## 填寫設定

先執行 `umbra keygen`，按[快速開始](/zh-hant/docs/getting-started/quick-start/)取得金鑰並選擇 `short_id`。將下面內容保存為 `server.toml`，替換所有預留值和 `cover.example`：

```toml
listen = "0.0.0.0:443"
private_key = "<X25519_PRIVATE_BASE64>"
short_ids = ["<SHORT_ID_HEX>"]
dest = "cover.example:443"
server_names = ["cover.example"]
max_time_diff = "120s"
mldsa_seed = "<MLDSA_SEED_BASE64>"
```

`listen` 指定 TCP 接聽位址。設定包含私密金鑰和簽章種子，請限制讀取權限。

## 啟動並驗證

```sh
umbra server -c server.toml
```

Umbra 啟動時會先探測目標網站；探測失敗時會停止啟動。檢查目標位址、網域名稱和伺服器的網路連線後再重試。`prebuild = false` 只關閉後續週期更新，啟動探測仍會執行。

確認接聽連接埠已開放，然後用匹配的 Umbra 用戶端測試一次請求。普通瀏覽器或 TLS 探測工具看到掩護網站的憑證，是網站轉發路徑的正常結果。

## 依需求開啟 QUIC

在完整設定中增加：

```toml
udp_listen = "0.0.0.0:443"
```

TCP 和 UDP 可以使用同一連接埠號。為實際設定的 UDP 連接埠設定防火牆規則，並驗證實際網站的 QUIC 可達性。

前景執行驗證成功後，可繼續設定[背景服務](/zh-hant/docs/guides/deployment/)。
