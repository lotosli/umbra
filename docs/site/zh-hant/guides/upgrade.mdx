升級前查看目標版本的說明，記錄兩端目前使用的版本，備份設定，並保留已經驗證可用的程式。安排兩端的升級時間，避免協議變化導致連線中斷。

## 升級到 1.0.0-alpha

這一版本改進了加密處理、共享連線排程與 QUIC 資料接收。TCP 多路重複使用預設使用自適應流控：它會根據資料消耗和往返時間調整接收視窗，同時遵守記憶體預算。

使用自適應 mux 時，用戶端與伺服器端需要一起升級。

```toml
[performance]
adaptive_mux = true
quic_congestion = "bbr"
```

`adaptive_mux = false` 可顯式選擇舊 mux 模式。該設定適用於 TCP 多路重複使用；`mux = false` 仍選擇獨立 Vision 連線，`udp_transport` 仍單獨決定 UDP 的傳輸方式。

## 從更早版本升級

0.0.8 調整了 X25519MLKEM768 混合金鑰交換的資料順序。涉及該變化時，舊端點與新端點需要同步更新。查閱中間版本說明，確認是否還有設定或協議變化。

沒有金鑰輪換要求時，可以繼續使用原有身分金鑰、`short_id` 和網站名稱。

## 升級後驗證

1. 確認兩端實際執行的是剛安裝的程式。
2. 透過本機 SOCKS5 完成一次 HTTPS 請求。
3. 如果設定了 UDP，測試實際使用的 UDP 應用程式。
4. 檢查程序重啟後能否恢復連線。
5. 若要比較效能，保持網路路徑、應用程式負載和測試方法一致。

QUIC 預設使用 BBR；其設定作用於 QUIC 發送，與操作系統的 TCP 擁塞控制分別管理。出現問題時，保留錯誤資訊並按對應版本的兼容要求還原兩端。
