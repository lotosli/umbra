Umbra 使用三個子指令完成日常操作：`server` 啟動伺服器端，`client` 啟動本機 SOCKS5 代理，`keygen` 產生身分金鑰。

## 查看幫助

```sh
umbra --help
umbra server --help
umbra client --help
umbra keygen
```

已安裝版本的具體選項可通過對應的 `--help` 查看。

## 讀取和覆寫設定

使用 `-c` 或 `--config` 指定 TOML 檔案。命令列選項覆寫對應欄位；未提供的選項繼續使用檔案值。

伺服器端的 `--short-ids` 和 `--server-names` 接受逗號分隔的清單。`--mux`、`--prebuild` 需要顯式填寫 `true` 或 `false`。效能選項通過 TOML 的 `[performance]` 表設定。

## 啟動伺服器端

```sh
umbra server -c server.toml
```

| 指令 / 選項 | 用途 |
|---|---|
| `-c, --config` | `server.toml` |
| `--listen` | TCP 接聽位址，IP:連接埠 |
| `--udp-listen` | 覆寫設定檔案中的 QUIC UDP 接聽位址 |
| `--private-key` | X25519 私密金鑰，Base64 解碼後為 32 位元組 |
| `--short-ids` | 至少一個十六進制 ID；每項 0–8 位元組 |
| `--dest` | 掩護網站位址，host:port |
| `--server-names` | 允許的掩護網站網域名稱清單 |
| `--max-time-diff` | 允許的時間戳偏差，至少 1 秒 |
| `--mldsa-seed` | ML-DSA 簽章種子，Base64 解碼後為 32 位元組 |
| `--prebuild` | 週期更新目標；啟動探測始終執行 |
| `--padding-scheme` | 業務資料填充策略 |
| `--tcp-evasion` | TLS 握手訊息分塊寫入策略 |

## 啟動用戶端

```sh
umbra client -c client.toml
```

| 指令 / 選項 | 用途 |
|---|---|
| `-c, --config` | `client.toml` |
| `--server` | Umbra 伺服器端，host:port |
| `--transport` | TCP 請求的傳輸：tcp 或 quic |
| `--udp-transport` | 覆寫 UDP 傳輸：tcp 或 quic |
| `--public-key` | 伺服器端 X25519 公開金鑰，Base64 解碼後為 32 位元組 |
| `--short-id` | 伺服器端允許的一個 short ID |
| `--server-name` | 伺服器端允許的掩護網站網域名稱 |
| `--fingerprint` | 瀏覽器握手設定檔名稱 |
| `--mldsa-verify` | 伺服器端 ML-DSA 驗證金鑰，非空 Base64 值 |
| `--socks-listen` | 本機 SOCKS5 位址，無密碼認證 |
| `--spider-path` | 實際網站存取路徑；以 / 開頭，不含回車或換行 |
| `--mux` | 加密多路重複使用；false 選擇獨立 TCP/Vision |
| `--padding-scheme` | 業務資料填充策略 |
| `--tcp-evasion` | TLS 握手訊息分塊寫入策略 |

## 產生金鑰

`umbra keygen` 輸出 `x25519_private`、`x25519_public`、`mldsa_seed`、`mldsa_verify` 四項 Base64 值，不必額外選項。按[快速開始](/zh-hant/docs/getting-started/quick-start/)分配到兩端設定。

輸出中包含私密金鑰。請保存在受保護的檔案中；日常啟動也優先使用設定檔案，避免秘密值出現在指令歷史或程序參數中。
