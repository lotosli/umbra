建議先使用預設值完成連線，再根據實際負載調整。用戶端與伺服器端都接受可選的 `[performance]` 表。

## 預設效能設定

```toml
[performance]
memory_mib = 512
group_memory_mib = 256
max_window_mib = 64
quic_stream_window_mib = 6
quic_send_window_mib = 32
adaptive_mux = true
diagnostics_interval_secs = 0
quic_congestion = "bbr"
```

| 欄位 | 預設值 / 要求 | 含義 |
|---|---|---|
| `memory_mib` | `512` | 程序邏輯記憶體預算，16–16384 MiB |
| `group_memory_mib` | `256` | 憑據組預算，至少 16 MiB，且不超過程序預算 |
| `max_window_mib` | `64` | 自適應總接收視窗上限，1–64 MiB |
| `quic_stream_window_mib` | `6` | QUIC 單流接收視窗，1–64 MiB |
| `quic_send_window_mib` | `32` | QUIC 保留發送存儲，1–64 MiB |
| `adaptive_mux` | `true` | 用戶端新 TCP mux 會話的自適應開關 |
| `diagnostics_interval_secs` | `0` | 伺服器端診斷週期：0 為關閉，範圍 1–3600 秒 |
| `quic_congestion` | `"bbr"` | 本端 QUIC 發送擁塞控制演算法：bbr、cubic、new-reno |

## 設定記憶體和視窗

記憶體預算約束應用程式承諾給連線的資源。共享同一憑據的連線共用組預算；按程序和憑據組管理資源，便於控制併發連線的佔用。

`memory_mib` 接受 16–16384 MiB；`group_memory_mib` 至少為 16 MiB，並且不超過程序預算。視窗欄位接受 1–64 MiB，實際視窗還會根據預算裁剪。

這些值用於邏輯資源管理，並非啟動時一次性分配的記憶體，也不是操作系統顯示的 RSS 上限。為核心緩衝、分配器、握手和其他服務留出空間。共享預算以憑據為單位，多個使用者共用憑據時歸入同一組。

## 使用自適應 mux

`adaptive_mux` 控制用戶端新建 TCP 多路重複使用會話的流控方式。接收視窗根據實際資料消耗和往返時間增長，增長前先申請相應預算。

這一設定在 `mux = true` 時使用。`mux = false` 繼續選擇獨立 Vision 連線。升級自適應 mux 時，兩端使用兼容版本。

## 選擇 QUIC 擁塞控制

`quic_congestion` 支援 `bbr`、`cubic` 和 `new-reno`，預設 `bbr`。設定影響本端發出的 QUIC 流量；用戶端與伺服器端可分別設定。系統 TCP 擁塞控制仍由操作系統管理。

## 設定流量填充

預設策略在每個方向前 16 次業務寫入的前後，各加入一個 100–1400 位元組的隨機填充幀；此後每 32 次業務寫入加入一個填充幀。

- `default`：使用上述預設策略。
- `none`：關閉填充。
- `early=N,min=N,max=N,later=N`：自定義早期寫入次數、填充位元組範圍和後續間隔。`later=0` 關閉後續填充。

`min` 不得大於 `max`，`max` 不得超過 65535。啟用早期填充時，`max` 必須大於零。填充增加額外帶寬消耗，調整後應驗證實際連線。

## 設定 TCP 握手分塊

`segment` 按順序分塊寫入 ClientHello，預設閾值為 64 位元組、首塊為 32 位元組。`off` 使用普通寫入，也可用 `segment:threshold=N,first=M` 自定義。目前不接受 Geneva 策略。

```toml
padding_scheme = "default"
tcp_evasion = "segment"
```

這兩個欄位屬於頂層設定，請放在 `[performance]` 表之前或檔案中的頂層欄位區域。

## 啟用診斷

伺服器端將 `diagnostics_interval_secs` 設為 1–3600，可按指定秒數輸出數值診斷；設為 `0` 時關閉收集與報告。診斷區分外層傳輸與目標連線的位元組數，並省略位址、SNI、憑據和資料內容。

閱讀指標時按下列含義判斷：

| 指標 | 如何理解 |
| --- | --- |
| 邏輯記憶體承諾 | 應用程式為連線保留的資源預算；實際記憶體佔用另看操作系統指標 |
| 寫入接受計數 | 本機寫入接口接受的資料量；目標應用程式收到多少需在目標端確認 |
| 排程 poll 時間 | 任務推進過程中的牆鐘耗時；CPU 使用率另看系統指標 |

每次只改一組相關參數，在相同負載下比較，再決定是否保留。
