選型時先看三件事：網路允許哪些連線、準備如何維護伺服器，以及現有應用程式如何連接。Umbra 將網站掩護、TCP/Vision、QUIC 和 SOCKS5 入口放在一套用戶端與伺服器端中，適合希望自行管理這套連線的使用者。

以下按 Umbra 1.0.0-alpha 和列出的官方資料說明功能差異。Xray 一欄限定為 VLESS + REALITY + Vision 的 TCP 組合，便於與具體部署方式對照。


內容複核：2026-09-18.

## 部署與傳輸對照

| 方案 | 主要特點 | 部署要點 | TCP 與 UDP |
| --- | --- | --- | --- |
| Umbra | 實際網站掩護；一個本機入口可設定兩條傳輸路徑 | 伺服器與用戶端安裝相同版本的 Umbra，以命令列啟動。使用 QUIC 時須開放 UDP 連接埠，並選擇支援 QUIC 的掩護網站。 | TCP 可選連線重複使用或 Vision；UDP 可單獨使用 QUIC |
| Xray + VLESS + REALITY + Vision | 在 Xray 中組合 REALITY 與 Vision | 兩端設定相同的使用者 ID；用戶端填入伺服器對應的 REALITY 身分參數，並將 flow 設為 xtls-rprx-vision。 | 此處為 TCP 外層；UDP 請求按 flow 和用戶端設定處理 |
| VMess AEAD | 協議提供加密，可搭配不同傳輸 | 兩端使用相同的使用者 ID 和傳輸方式；選用 WebSocket 時對齊路徑，啟用 TLS 時設定網域名稱與憑證。 | 支援 TCP、UDP 請求，外層由設定決定 |
| Trojan | 使用 TLS，並支援未認證請求轉送到網站服務 | 設定伺服器網域名稱、有效憑證和密碼，用戶端填入相同密碼。標準 Trojan 的 UDP 請求也透過 TCP 連線傳送。 | TCP 與 UDP 請求通過 TLS/TCP 承載 |
| Shadowsocks AEAD / 2022 | 基於金鑰的加密代理 | 兩端使用相同的加密方式與金鑰；需要 UDP 時開放對應連接埠。額外外掛須依其說明在兩端設定。 | 基礎協議支援 TCP、UDP；插件支援範圍單獨確認 |
| Hysteria 2 | 基於 QUIC；未認證時提供 HTTP/3 網站行為 | 開放伺服器 UDP 連接埠，設定 TLS 憑證與驗證資訊。若網路封鎖 UDP，須改用其他可行的連線方案。 | TCP 使用可靠 QUIC 流，UDP 使用不可靠資料報 |

對應的官方資料：[Xray VLESS/Vision](https://xtls.github.io/config/outbounds/vless.html)、[VMess](https://www.v2fly.org/developer/protocols/vmess.html)、[Trojan](https://trojan-gfw.github.io/trojan/protocol)、[Shadowsocks 2022](https://shadowsocks.org/doc/sip022.html)、[Hysteria 2](https://v2.hysteria.network/docs/developers/Protocol/)。

## Umbra 可以簡化哪些工作

### 兩條路徑，共用一個本機入口

設定 `transport = "tcp"`、`udp_transport = "quic"` 和 `mux = false` 後，TCP 請求使用 Vision，UDP 請求使用 QUIC。應用程式只需要一個 SOCKS5 代理位址，兩端各執行一個 Umbra 執行個體。

### 減少憑證維護

Umbra 使用身分金鑰和暫時憑證繫結，節點不必自行申請和續期公開網路 CA 憑證。你維護兩端金鑰，並選擇可達的實際網站。啟用 QUIC 時，目標網站也需要支援 QUIC。

### 沿用應用程式與規則

支援 SOCKS5 的應用程式可直接連接；Clash 類用戶端可以保留規則和介面，將遠端傳輸交給 Umbra。連線兩端使用 Umbra，現有其他協議節點仍由對應用戶端處理。

### 按請求選擇連線方式

TCP mux 重複使用連線，減少重複建連；獨立 Vision 連線針對符合條件的 TLS 1.3 流量減少重複加密。選擇方法見[傳輸模式](/zh-hant/docs/concepts/transports/)。

## 按已有環境選擇

- **已經使用 Xray 與 REALITY：** 先評估現有路由、用戶端和設定管理需求。Umbra 的重點是一套用戶端與伺服器端中的單入口雙傳輸體驗。
- **已有 VMess 應用程式：** 確認正在使用的傳輸組合和用戶端支援，再評估遷移工作量。
- **希望按常規 TLS 服務維護：** 可以瞭解 Trojan 的憑證與轉送部署方式。
- **希望採用金鑰設定的加密代理：** 可以瞭解 Shadowsocks，並依需求要評估額外插件。
- **主要考慮 QUIC 路徑：** 對照 Hysteria 2 的資料報與 Umbra 的可靠流方式，測試實際 UDP 應用程式的表現。

Umbra 目前以 Alpha 命令列程式交付。選型還應考慮圖形介面、移動端與訂閱管理等現有需求。

## UDP 的一個關鍵差別

Hysteria 2 使用不可靠資料報承載 UDP；Umbra 目前把 UDP 關聯資料封裝在可靠 QUIC 流中。前者允許丟失資料報，後者會在同一流中等待缺失資料重傳。對通話、遊戲或其他即時應用程式，應在實際網路上比較延遲與丟包表現。[Hysteria 2 協議](https://v2.hysteria.network/docs/developers/Protocol/)
