## ADDED Requirements

### Requirement: Chrome profile loading
The system SHALL load named TLS and QUIC fingerprint profiles from data files instead of hard-coded protocol tables.

#### Scenario: Known profile loads
- **WHEN** `chrome-latest` is requested
- **THEN** the returned profile contains cipher suites, extension order, GREASE slots, groups, signature algorithms, ALPN, and padding policy

#### Scenario: Unknown profile is rejected
- **WHEN** a profile name is not present in the fingerprint data directory
- **THEN** loading returns an explicit error

### Requirement: JA3 and JA4 self-check
The system SHALL compute JA3 and standards-conformant JA4 identifiers from generated ClientHello bytes for comparison with the target profile. JA4 SHALL follow a pinned authoritative algorithm definition and independently sourced fixtures, including transport context, GREASE exclusion, field normalization, sorting, and hash formatting. The existing custom JA4-style value SHALL NOT be labeled or accepted as standards-conformant JA4.

#### Scenario: Generated hello matches profile identifiers
- **WHEN** a ClientHello is built from a profile fixture with independently verified expected identifiers
- **THEN** the computed JA3 and standard JA4 equal those expected identifiers

#### Scenario: JA4 has independent conformance evidence
- **WHEN** captured or published ClientHello fixtures are checked against a pinned independent JA4 reference
- **THEN** production JA4 matches the reference rather than merely matching a stored value generated by the same custom implementation

### Requirement: QUIC fingerprint data
The system SHALL represent QUIC version, transport parameter order, GREASE transport parameter policy, ALPN, SCID length, and HTTP/3 settings in the profile.

#### Scenario: QUIC profile preserves parameter order
- **WHEN** a QUIC profile is loaded and serialized for a test handshake
- **THEN** transport parameters appear in the configured order

### Requirement: Production ClientHello evidence
Fingerprint validation SHALL exercise the production ClientHello builder and compare decoded extension payloads with a versioned real Chrome capture. Normalization SHALL be limited to explicitly documented per-connection randomness and caller-controlled fields. JA3 and the existing JA4-style identifier SHALL NOT substitute for full payload validation.

#### Scenario: Malformed extension fails the fingerprint gate
- **WHEN** the production builder emits a malformed compression vector or an empty ECH extension for a capture containing a structured ECH GREASE payload
- **THEN** fingerprint validation fails even if extension identifiers and JA3 still match

### Requirement: Structured ECH GREASE and randomized fields
Profiles SHALL represent the captured ECH GREASE payload structure and permitted length policy. Production generation SHALL use fresh random fields where the captured browser does, with injectable deterministic randomness for tests, and SHALL NOT claim to implement real ECH encryption merely by emitting GREASE.

#### Scenario: Repeated connections follow the captured profile
- **WHEN** several ClientHellos are generated for a capture-backed profile
- **THEN** ECH GREASE payloads are nonempty and structurally valid, randomized fields vary as specified, and invariant payload fields retain the captured shape

### Requirement: Evidence-based padding and transport claims
Padding SHALL follow the selected profile's actual extension placement and length policy, not an unconditional target inferred from one capture. TLS capture evidence SHALL NOT be presented as proof of QUIC fingerprint parity.

#### Scenario: Profile has no padding extension
- **WHEN** the captured extension list omits extension 21
- **THEN** the builder does not insert that extension solely to reach a historical single-record byte count

#### Scenario: QUIC lacks a capture fixture
- **WHEN** QUIC values are inherited seed data without a matching decoded Chrome Initial capture
- **THEN** validation reports QUIC parity as unverified rather than passing it as capture-validated
