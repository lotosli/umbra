# Completion audit against the original multi-client plan

This audit uses the original nine-part conversation plan as well as the change artifacts. A checked implementation task, passing tests or an existing release is not proof that the whole plan is finished. The earlier release is deployed, but overall completion remains unproven.

| Original requirement | Current evidence | Audit result |
|---|---|---|
| Process / credential group / outer / logical stream ownership | Canonical identity in dispatch; Resources and BudgetPool shared across authenticated server transports; retained leases in workers and mux chunks | Implemented; arithmetic and runtime lifecycle tests cover shared credentials and reclamation |
| Independent upload/download progress | Concurrent relay directions; independent adaptive receive state at each endpoint; reverse-backpressure and asymmetric-window tests | Implemented for the changed mux/relay paths |
| Path-specific receive growth, proactive credit | flow.rs consumption/RTT growth, bounded stream and aggregate cumulative limits; single-path and mixed-link diagnostics; native aggregate consumption/RTT controller | Implemented for TCP mux and native QUIC aggregate credit. Native QUIC's per-stream receive window remains fixed; aggregate tuning does not remove that distinct limit |
| Global/group memory, startup headroom, no revoked/double-lent grants | BudgetPool admission/growth limits and last-owner release; explicit native receive/send/staging and per-stream terms | Fixed 64MiB native admission was reproduced failing at 16MiB, then corrected to funded smaller startup/growth. The actual low-memory connection now transfers exact bytes and releases its commitment; growth/retained-reader invariants pass. Initial admissions still obey finite hard ceilings |
| Cumulative stream + connection limits, negotiation, FIN/RST | FlowSettings/CreditUpdate parsers; AdaptiveFlow and MuxSession; malformed credit, legacy, half-close/reset tests and seeded fuzzing | Implemented and tested |
| Active-group work-conserving scheduling; multiple outers do not define identity | Shared ready-task gate for authenticated Vision/mux/TLS/QUIC/UDP tasks; group then task round robin; Tokio worker-count permits | Implemented in source. Equivalent 8-vs-1 ready tasks changed from 80,000/10,000 to 45,001/44,999 polls. Blocking, cancellation, concurrent wakes and borrowing all parallel permits pass. Actual multi-credential TCP runtime and native QUIC snapshot tests verify integration. This is poll-opportunity fairness, not equal Mbps or equal CPU time for unlike polls |
| Lower data-path work with preserved ownership | Direct DATA encoding, owned chunks, incremental totals, reused frame/record buffers, in-place AEAD, worker ownership, QUIC receive batches | Implemented. Bridge replacement and cached cipher contexts remain conditional candidates; current Vision CPU evidence does not support doing them for this WAN path |
| Per-mode/client/direction goodput and bottleneck observations | Benchmarks; FlowSnapshot; mixed-client credit/output wait measurements; live Vision process/TCP profile; per-group scheduler task/queue/poll observations | Partial: production diagnostics do not yet expose all per-group/direction credit, socket, queue and budget causes; the live profile covers one Vision download only |
| Simultaneous heterogeneous clients / paused readers / demand changes | mixed_throughput.rs: four outers, three groups, 20/100/200ms RTT, 10/100/1000Mbps paths, 1/4 streams, one common 500Mbps serializer, held consumption until another client finishes; all leases reclaimed | Concrete progress/isolation evidence. Changing demand is covered by early completions and release of the held consumer. This is a MuxSession emulator, not full real-network cross-transport fairness or CPU-saturation proof |
| Quinn BBR latest requested pair, selectable per endpoint | quinn 0.11.12 / proto 0.11.18; actual controller type test; selected BBR at both installed endpoints; successful QUIC traffic | Implemented. No measured BBR advantage is claimed |
| 0.0.9 artifacts and paired deployment | Published asset digests match both running executables; authenticated HTTPS/UDP/mux/QUIC checks | Deployed implementation verified. Test/document-only audit updates do not change executable code; any further production fix requires reconciling release artifacts |
| Required gates and final integration | Group-scheduler source: local cargo xtask ci passed 523 tests, 95.01% lines; strict OpenSpec; earlier parser fuzz run | A pre-existing config-only test had a transient nextest pipe-leak label and passed its targeted instrumented rerun without the label. GitHub Actions billing failure still prevents remote CI/integration and subsequent archive |

Next implementation review should complete the remaining data-path observation requirements. Native admission and group scheduling change production code and have not yet replaced the published/deployed artifacts. Do not release live credit or mark the complete plan done merely because current traffic succeeds.
