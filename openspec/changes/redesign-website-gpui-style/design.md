# Design

## Context

动机与范围见 proposal.md。当前网站使用独立 React/TanStack/Fumadocs workspace，视觉主要集中在 site.css 与营销组件。现有首页容器为 1160px，标题 weight 300，大量说明为 10–13px，主色为靛蓝，深色背景偏蓝。重做需要同时改变构成、字体层级和颜色。

参考来源：https://gpui-kit.com/ ，2026-09-18 实际浏览浅色、深色首页并读取计算样式。在 1272px 视口下，参考站 H1 约 55px / weight 660，H2 约 46px，首屏说明约 16.5px；白底 #ffffff、正文 #0a0a0a、次文字 #737373；深色背景 #0a0a0a、正文 #fafafa、次文字 #a3a3a3、代码面板 #151515。下述尺寸是 Umbra 的实施目标，不宣称全部来自参考站测量。

## Goals / Non-Goals

**Goals:** 以同样的黑白灰层次、粗体标题、空间比例与代码展示建立整站一致体验；通过可读性和内容布局解决“小气”的观感。保留现有七语 SSR 内容及交互合同。

**Non-Goals:** 不改 Rust、协议行为、域名或发布配置，不增加新产品功能，不复制参考站品牌和产品数据，生产发布使用既有 Cloudflare 手动发布流程。

## Decisions

### 1. 统一中性色设计变量

在原有语义变量上重构，Fumadocs 映射同源。浅色采用上述实测背景与文字；面板 #fafafa、边框 #e5e5e5、黑色主按钮。深色采用上述实测深色值，边框 #262626、浅色主按钮。少量绿用于状态，代码语法使用克制的紫/绿。选择系统无衬线栈及系统等宽栈，保持各系统 CJK 回退。相比只改 accent，这样可消除全站蓝灰底色与正文对比度不足。

### 2. 宽幅布局与字体比例

- 主容器最大 1440px，桌面两侧 32–48px，手机 20px；文档正文独立保持约 760px 阅读宽度。
- 导航约 60–64px 高，字号 14px；空间不足时切移动导航，不能通过缩小字体硬塞七语标签。
- 首屏桌面双栏约 46:54，间隔 48–64px，上下留白 72–96px；960px 以下单栏。
- H1 随屏幕约 48–76px、weight 650–700、紧凑行距；手机约 38–44px。H2 桌面约 40–48px、手机 30–36px。描述 16–18px，卡片正文 14–16px，控件 14px；辅助文字通常至少 12px。
- 容器保持自然文案换行，不用固定高度裁切；主按钮高度至少 44px，边角 6–8px，面板 12–16px。

### 3. 首页构成

导航 → 浅网格首屏（左：alpha 版本标记、粗体产品主张、说明、开始使用与协议入口、真实平台与许可信息；右：带窗口栏的大代码面板）→ 产品能力网格 → 宽幅入门区 → 文档入口 → 收尾 CTA → 页脚。

代码窗口优先复用仓库已有且可验证的 clone/build/keygen 命令，提供复制反馈，不添加模拟运行结果、实时吞吐或虚构 UI 截图。协议关系图保留在协议页面并放大标签。首屏不再以小型环形示意图作为主要视觉。能力卡片采用均衡网格与真实能力内容，较少装饰、较大的排版空间。

### 4. 其他页面

下载页以清晰的平台分区与大尺寸操作入口呈现；协议页使用分层原理说明与宽幅图示；安全页突出已实现边界和限制；更新页使用可读的版本列表与详情。共享页眉、页脚、按钮、代码块和标题组件。文档页保留目录、文章、页内导航结构，同步中性色、字体和阅读间距；搜索弹层及空状态一起适配。

### 5. 实现策略与验收

直接重构原有样式规则与必要组件，删除被取代的样式，避免末尾叠加大量覆盖规则。无新 UI 框架依赖。新增或改写可见文案必须同步七语。复用现有交互测试，仅为新增可观察要求补测试。

验收视口为 1440、1280、768、390、320px：所有页面无全页横向滚动；代码只在自身容器滚动。七语首页和各页面模板均检查，重点视觉检查英文/简中和长文案语言；浅深两主题截屏检查。键盘焦点、搜索、语言切换、复制、主题持久化、移动导航、SSR 与 404 回归。记录实际通过和未通过状态。

## Risks / Trade-offs

- 大标题与七语长度不同 → 自然换行和响应式列布局，检查日文与法文等语言，禁止截断关键文字。
- 中性色可能弱化品牌 → 保留 Umbra 字标与月蚀标记，靠构图与产品内容表达品牌。
- 共享变量影响文档 → 文档正文、代码、侧栏、目录、搜索分别验收；正文保持阅读宽度。
- 本机默认 Node 为 v26.8.2，与仓库要求不符 → 实现阶段切到仓库要求的 Node 24.18.1 / pnpm 9.11.0，再运行前端闸门。

## Migration Plan

规格批准后执行任务清单，在本地运行 build → check → test（行覆盖率 >=90%）→ test:e2e 并提供浏览器预览。无需数据迁移。源码改动可通过常规 Git 回退；用户已明确授权生产发布，必须先通过验证再执行。
